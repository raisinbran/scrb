### A-711 — 2026-11-16 — cloud implementation — Mic Test mock lost its only sample after inactive-meter gating

- **Observed effect:** PR #330's earlier paused-meter fix kept inactive meters at the floor but its existing Mic Test UI regression began failing deterministically on both macOS and Windows ([CI 44016223195](https://github.com/raisinbran/scrb/actions/runs/44016223195)): the test expected -24 dB, but saw -100 dB.
- **Source evidence and attribution:** In `mock-backend.ts`, `startAudioCheck` emits `audioCheck(active=true)` and immediately a single `levelMeter(-24)`. React has not yet committed the `active` prop and its associated effect subscription, so the initial sample is correctly ignored. The prior cloud fix introduced the new gating but did not adapt the test to its timing. The independent [review](https://github.com/raisinbran/scrb/pull/330#pullrequestreview-5932827218) identified this omission.
- **Correction:** Commit `fe1e7f4c77c5eba1ebc0fe14eadd058f6cfe9bc9` adjusts the Mic Test regression: wait until the active `Stop test` button appears, then emit a subsequent `levelMeter` sample inside React `act` and verify that the meter rises. No production gating or native capture changes; the Pause/Resume/Stop regression remains.
- **Remaining risk:** Exact-head macOS/Windows CI and independent review are pending; the native mic test was not measured, and the earlier Windows summary-retention test failure remains to be evaluated if reproduced. No private recordings were accessed.
