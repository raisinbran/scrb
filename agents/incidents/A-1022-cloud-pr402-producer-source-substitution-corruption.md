### A-1022 — 2026-11-21 — cloud GitHub — producer PowerShell source corrupted by JavaScript replacement expansion

- **Confirmed failure:** PR #402 first corrected implementation HEAD 3ade36cdcd9868160554df7e10ef8bc3fa2680ff failed the Windows CI unit suite in run 44919885777. The Windows-only PowerShell parser regression correctly rejected scripts/package-win-installer.ps1: regex strings containing a literal dollar sign followed by a quote were expanded by JavaScript String.replace replacement-text semantics, inserting multiple copies of the script trailer. The package script had invalid PowerShell syntax. The CI log shows "UnexpectedToken" and "MissingEndParenthesisAfterStatement" in the affected regex.
- **Cause and attribution:** Agent-authored GitHub blob transformation used string replacement text instead of a callback, allowing dollar-apostrophe replacement metacharacters to expand. This repeated the same class of mistake previously recorded as A-1016 on the older PR #402 task; the source check failed to catch the recurrence before commit.
- **Observed effect:** One avoidable red Windows CI at a superseded head. macOS CI and the guard-only workflow succeeded, but no actual package, NSIS installer, source-built tools or customer data was executed or changed. No manual CI retry was launched.
- **Correction:** Rebuilt the PowerShell script from the untouched original verified PR source using a callback replacement that inserts dollar characters literally; verified one trailer and intact producer-run regex before publishing the corrected commit. Preserve the original failed CI and exact offending head in PR history.
