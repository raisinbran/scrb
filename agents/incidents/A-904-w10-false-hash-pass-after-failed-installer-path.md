### A-904 — 2026-11-19 — W10 hash-verification success message printed after installer lookup failed

- **Classification:** Confirmed assistant-authored verification-script safety/reporting failure, not a Scribe application defect.
- **Event:** The interactive `Read-Host` value for the Windows installer included enclosing double quotes, which PowerShell kept literally. The resulting path was interpreted as drive `"C`, so `Test-Path`, `Get-Item` and `Get-FileHash` failed for that installer. A prior assistant instruction said paths should be unquoted, but the provided verification workflow did not explicitly handle quoted input and then **printed an unconditional all-three-PASS message after the failure** when the owner executed each command interactively.
- **Detection:** Owner supplied the exact failing PowerShell transcript. This defect was not detected during the original guidance's preparation and was recognized only after the owner shared the output. Distinct from A-902, the owner's earlier detection of a missing backslash in a separate copy-ready path.
- **Impact:** The installer had **NOT** passed the independent full SHA-256 check at that point, despite the printed PASS line. Unpacked-app and model-manifest hash commands produced no errors, but no global three-file PASS was valid. No installed-app execution, data loss, file mutation, or security bypass is shown. The failure alone does not demonstrate that the installer file is absent.
- **Correction:** In existing normal non-elevated host PowerShell, strip enclosing quotes from the already-read path with `$installer.Trim('"')`, then perform all three existence/hash checks and installer size check inside a **single invoked script block** (`& { ... }`) with `$ErrorActionPreference = 'Stop'`, `-ErrorAction Stop` for data reads, and **one final SUCCESS message within the same block only after all checks**. Copyable corrected code provided in chat. This rechecks integrity but does not install models or Scribe.
- **Prevention:** Parse or reject quoted path input deliberately; require fail-closed scripts, never unconditional success lines after separately entered interactive commands; verify any displayed PASS against a completed integrity checklist. Retain user-reported path/source qualifiers and don't claim host access not performed.
- **Evidence:** [Issue #340 public report](https://github.com/raisinbran/scrb/issues/340#issuecomment-7033086101) and owner-provided console transcript.
