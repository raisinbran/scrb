### A-411 — 2026-11-15 — Claude Code / Sonnet 5.5 / Windows PC Regiurn — an unintended package fetch, and a test that left stand-in processes running
- **Status / attribution:** Confirmed agent error (tool use and test design); no product defect, fixed in the same session.
- **What failed:** (1) In a fresh worktree with no `node_modules`, `npx prettier` printed that it would install `prettier@3.10.1` from the registry and did so, a download I had not intended and had not asked about. It formatted one file; nothing from it is in the repo. (2) The first version of the new end-to-end test killed its stand-in "app" but not the child process below it, so two copies of `node.exe` named `whisper-server.exe` kept running and locked their temp folders (`EPERM` on cleanup).
- **Impact:** One small unrequested npm download, two stray processes and two temp folders until they were stopped and removed by hand. No effect on any meeting or recording.
- **Source evidence:** The `npx` output line "The following package was not found and will be installed"; the two failing cleanup steps in the first test run; the later process listing showing no remaining stand-ins.
- **Correction / remaining risk:** The worktree now has the same `node_modules` links as the other checkouts, and the test ends the whole process tree with `taskkill /T` before removing its folder. Check that dependencies are linked before running any `npx` tool. Negligible risk.
