# A-1051 — PR #421 handoff GitHub metadata and required-argument mistakes (2026-11-22 PT)

- **Attribution:** Two avoidable non-production GitHub connector-call errors made during publication of the November 22 M1/V1 handoff. These were cloud task tooling mistakes, not repository runtime, encryption, Windows installer or production tests.
- **First error:** A read-only GitHub REST branch-metadata URL encoded a slash-containing branch as a single path segment and received 400 INVALID_ARGUMENT. The independently successful branch commit had already been written and was subsequently verified through fetch_file at its exact Git ref. No repository content was changed or corrupted by this failed read.
- **Second error:** The first create_pull_request call omitted the required repository_full_name argument and failed schema validation before GitHub mutation. Retried once with the correct required field; draft PR #421 was successfully created.
- **Correction/evidence:** Verified committed handoff bytes using fetch_file at the exact commit; PR #421 is draft and contains the handoff and original 12-column usage row. This incident and a supplemental usage row account for publication errors without rewriting the earlier usage record.
- **Prevention:** For a branch name with slashes, use the GitHub connector's known ref-aware fetch_file instead of constructing an encoded branches REST path; validate required arguments against the exact mutation schema before submitting.
- **Collision check:** A-1051 was absent from current main's public incident list and all 39 then-open PR changed-file inventories including #420/#421. Unpublished machine-local reservations are unavailable and not deemed cleared. No private media, key, installer, host action or CI rerun occurred.
