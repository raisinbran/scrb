## Native-first feasibility, with hard limits

- **macOS:** Apple supports user-facing Mic Modes; `NSAlwaysAllowMicrophoneModeControl` may expose their selection before capture, but Scribe's current raw HAL microphone path is not proven to carry this processing. A prior `AVAudioEngine` voice-processing spike ([#160](https://github.com/raisinbran/scrb/pull/160), [results](mic-echo-spike-results.md)) reduced mic echo by at least 15 dB yet attenuated meeting audio by about **9 dB**, violating the project rule. Its default remains off; **do not enable `SCRB_VOICE_AEC=1` by default** or assume native Mic Mode avoids the same problem.
- **Windows:** Microsoft supports Voice Focus through Windows Studio Effects on **select** NPU/driver-equipped machines, and Windows allows capture-mode/effects inspection on supported endpoints. Assess device availability and actual samples. Raw capture can bypass some APO effects, but always-on endpoint/driver/hardware processing is possible; do not represent raw capture as proven bit-perfect without evidence.
- **Discord** is a UI precedent, not proof that it uses Apple's Mic Modes for its Input Profile settings. No dependency on Discord.
- **Preservation:** The approved V1 requirements say mic and meeting original tracks are unprocessed and must remain available for reprocessing. A native system mic effect that irreversibly changes Scribe's only saved audio does **not** fulfill this promise by itself. Confirm a safe simultaneous raw path or choose a separate recognition-only processing copy; do not risk double capture, drift, gaps, driver contention or output ducking.
- **Fallback:** If native support is absent or fails these conditions, evaluate a cross-platform local DSP option (for example, WebRTC APM for echo/AGC and RNNoise/DeepFilterNet-class suppression) with bounded CPU/memory and measurable transcription benefit. Echo-only post-final word matching (`dropRoomEcho` or its planned improvement) remains a separate fallback and is **not** equivalent to functional live echo cancellation.
- **Quality metrics:** Compare raw versus processed mic fidelity, false suppression of near-end voice during double-talk, transcription errors, echo level, speech start/end, CPU/memory, timing/drift, other apps' audio level and saved-chunk integrity. Predeclare quantitative improvement thresholds in an independently reviewed implementation plan; do not invent thresholds here. Keep the previously established **0.5 dB** maximum output-attenuation check.

## Milestone and scope boundaries

- **M1:** microphone processing may be deferred based on adequate current transcription quality, **without claiming the inactive controls function**. M1 evidence must mention this limitation.
- **V1:** every originally promised audio control must work on Mac and Windows, or an explicit owner-approved amendment must narrow the V1 requirement. A setting that simply saves to disk, an inactive feature hidden by a mock, or an unmeasured native feature is **not accepted**.
- **Gate 2:** remains closed; do not add retroactive acceptance criteria or change its sign-off.
- **Gate 8:** validate the controls in installed builds on both platforms using the linked checklist. Existing 8-hour capture/safety requirements remain unchanged.
- **Other Settings gaps:** fake model-update/revert functionality is also tracked in #335, but is **not** implemented or silently waived by this microphone-focused workstream.
