## 2. Product and generation

Before recording, paste an indented agenda into a local draft and attach it to the new meeting; or paste/edit it in a completed meeting's Notes view. Preview the tree, correct levels, retain original wording/order (including duplicate titles), and save. No generation during capture; use the resolved final transcript. Click **Generate notes**, see progress/cancel and review a document with the original hierarchy plus proposed off-agenda topics. Empty topics say “No discussion found” only after complete processing; otherwise show incomplete coverage.

Generate one factual bullet at a time: decision/status, significant information, caveat/risk, date/quantity, action/owner or open question. Preserve tentative, conditional, disputed and superseded statements. Agenda owner labels are hints, not evidence of assignments; use “Not specified” when unknown. New topics are grouped without forcing them into existing headings.

Process all chronological chunks, with overlap and stable topic IDs/parent context; extract candidates (including ordinary facts/caveats) and map them to agenda IDs or proposed new topics. Compare across chunks for duplicates, cross-topic returns and later reversals; cite both earlier and later evidence for a changed decision. Use structured JSON and deterministic rendering, not unconstrained prose. Reject invented IDs, out-of-chunk citations and unsupported claims; use bounded retry/split and visible missing-range warnings. Every generated bullet and new heading has one or more verified source spans (word IDs, time range, transcript revision/hash); lexical overlap alone is insufficient to verify dates, roles or polarity.

Each proposal opens the source words and audio. Accept, reject, edit, move or undo individually; no automatic acceptance. Store decisions separately from proposals, retain manual edits/rejections on rerun, and require re-review of stale or ambiguously relocated citations after transcript/agenda changes. A cancelled or superseded run cannot overwrite edits. Keep a versioned meeting-local notes document, separate from transcript, deleted with the meeting; no indexing of text or cloud calls. Export accepted/manual text as Markdown first (nested lists, exact levels/order, optional time references); DOCX next using real paragraph/list indentation and equivalent source references. A clean export omits pending/rejected proposals; explicitly label any user-entered uncited text. No change to existing summary/transcript exports.

## 3. Local models and evaluation

Minimum tier per [model test §2](outline-local-model-test.md): about 7–8B at 4-bit (6 GB GPU Windows machine, 16 GB unified-memory Mac per earlier hardware handoff; confirm actual available memory). Select an owner-approved installable 7–8B instruction GGUF first, with bounded context and CPU offload as needed. The existing Qwen3.5-9B Q4_K_M summary model is a comparator only if measured to fit; do not assume it does. Tier 2: about 14B 4-bit on the 12 GB GPU, optionally CPU offload on the weaker Windows machine. Freeze model/checksum, context, prompts, decoding, scorer and fixtures; benchmark memory, wall time and cancellation on all machines. No model download/run without approval.

Start with invented cases and AMI; compare existing Task A prompt vs agenda-aware extraction on identical transcripts. Then owner alone runs the approved offline harness on at least four previously recorded meetings (one >1 h), using the actual agendas, resolved transcripts and hand-finished notes. Gold notes never enter generation prompts; split development and held-out meetings before tuning. Owner marks reference facts not supported by the transcript separately (ASR omissions/external knowledge). Validate general/adversarial scorer suites with the actual selected embedding model and an invented-marker privacy test before private scoring. Private inputs, models, raw outputs and temporary artifacts stay outside Git on the owner's machine; network off, localhost only, numbers/fixed error codes only in reports (no names, paths, agenda, notes, recordings, excerpts or hashes of private content).

Score one-to-one atomic reference points: overall and correctly placed coverage, decision recall, date/quantity and owner recall (exact normalized values and roles), caveat recall, precision, new-topic recall/placement, duplicates. Hallucination rate = contradicted or unsupported generated claims / all generated claims, counted once; supported extra facts separate. Audit cited spans and classify every missing/incorrect claim; don't reward superficially matching wording. Report normalized bullet edit distance (insert/delete/substitute/move counts / reference bullet count), word edit distance and owner review time vs manual drafting; record actual accepts/rejects/edits/moves and rating. Report per-meeting counts, pooled rates and non-evaluable denominators. Keep the earlier Task A/B GO/STOP bars and minimum/rating rules for their campaign; proposed additional Task A product continuation bars: decision and date recall each ≥80%, hallucinations ≤5%, 100% valid citation ranges, ≥30% lower median active editing time than manual notes. Freeze with owner before private scoring; no single-meeting GO, no automatic ship decision.
