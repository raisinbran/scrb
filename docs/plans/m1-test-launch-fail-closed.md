# Plan: fail-closed M1 real-mode test launch (Mac and Windows)

**Planning only; no implementation authorized.** Audited `main` `aea9432e235975adf8c831c3c08a758661d54366` on 2026-11-17 (cloud-only). Related issues: #340, #349. This is a **test-launcher safety check**, not a change to normal Electron library fallback, storage, capture, security, IPC or contracts.

## Finding and scope boundary

- `scripts/m1.sh:70-73` and `scripts/m1.ps1:141-146` launch real-mode Electron after checking tools/models and already-running copies, **without** requiring a disposable `--user-data-dir` or `library-location.json`. Their `m1.test.*` harnesses test dependencies/process checks but not library isolation.
- `packages/storage/src/library.ts:1595-1604` returns `defaultRoot` for an absent, malformed or empty library pointer; `apps/desktop/src/main/backend.ts:76-79` supplies Documents/Meeting Scribe. `apps/desktop/src/main/main.ts:46-48` pins the default profile unless `--user-data-dir` was explicit. Thus an improperly configured **test launch may reach the owner's library** before an isolation assertion can run.
- Real Electron tests (`real-recording.spec.ts:12-15`, `real-final-pass.spec.ts:14-17`, `real-live-run.spec.ts:33-36`) create a pointer and launch, but do not first verify its contents or target. `real-live-run` intentionally retains evidence in `QA_EVIDENCE`, which need not be under OS temp.
- **No duplication:** draft #350 handles the shared-library notice and isolated-development location UI. #351 handles opt-in fictional-location seeding, and when its isolation validation fails the normal Electron startup still continues. Do **not** edit their `backend.ts`, `synthetic-location.ts`, `smoke.spec.ts`, contracts, or shared runbooks in this slice. Location seeding is not launch authorization. A hybrid mock meeting list is never an isolation test.

## Smallest test-only implementation

1. **One read-only validator:** add `scripts/m1-test-isolation.mjs`, exporting `verifyM1TestIsolation({ profile, library, allowedRoot })` and supporting a CLI. All three inputs must be **explicit**; no inferred/default path. Before launching anything, require an existing, readable profile directory and separately existing library directory; require a regular, readable `<profile>/library-location.json` containing JSON with a nonempty **absolute** string `root` equal to the expected library after canonicalization. Canonicalize the profile, library, allowed root and pointer using real paths; reject symlink/junction escapes, traversal, a pointer symlink, unreadable/missing targets, relative paths, and actual physical-directory aliasing on Windows (including junctions). Windows comparisons are case-insensitive: a letter-case-only difference is harmless if both paths resolve to the same physical directory; inconsistent physical identity or unverifiable canonicalization fails closed. Require distinct, non-nested profile and library directories under one uniquely named test root, itself inside OS temp **or** an independently authorized retained test-evidence parent; reject the allowed root itself, ordinary default profile/library, and paths outside the authorized test tree. Treat caller-supplied `QA_EVIDENCE` as a requested path, **never** as authorization to trust its parent. On uncertainty, error with a concise reason and nonzero exit; **never** create a library or use the Documents fallback. Test preparation, not this validator, creates the sibling directories and preseeded pointer.

   **Retained-evidence exclusion:** Before accepting a retained parent, identify and canonically resolve the ordinary application profile, the default Documents/Meeting Scribe library, and any library selected by the ordinary profile's `library-location.json` using metadata only (no meeting/audio reads). Canonically compare **both ancestor and descendant directions**: the retained parent, allowed root, profile, library, and their path components must be physically disjoint from every protected owner root (neither equal to nor within nor containing one). Resolve symlinks and Windows junction/reparse/drive aliases; compare physical directory identities for existing directories when path spellings alone cannot prove separation. Reject paths through an owner's library even if the final test folders have unique names. An unreadable/malformed owner pointer, an unknown relocated owner library, an unverifiable retained root, or indeterminate physical aliasing must **fail closed**; use a separately verified OS-temp test root instead. A retained parent needs independent test-only authorization, not merely `QA_EVIDENCE` or a marker written by the caller.
2. **Opt-in launcher mode only:** in `scripts/m1.sh` and `scripts/m1.ps1`, add an explicit `--test-launch` / `-TestLaunch` branch requiring validated profile, library and allowed-root arguments. Invoke the shared validator **before** invoking `npm` or Electron; abort on any failure. In the passing branch forward the validated exact `--user-data-dir=<profile>` to the existing `npm start -w @scrb/desktop -- ...` launch. Reject partial test arguments; leave unflagged ordinary owner recording launches byte-for-byte equivalent. Keep the existing native/model preflight and single-instance checks. Do not use `SCRB_DEV_AUTO_LOCATION=1` as a substitute for this guard; it may be set only after validation when the chosen profile meets #351's opt-in conditions.
3. **Direct test launches:** add a tiny adapter `apps/desktop/e2e/fixtures/isolated-real-launch.ts` that runs the same validator before `electron.launch`. Route only the three actual recording tests listed above through it, and prepare sibling profile/library directories (not `profile/library`). Preserve the deliberate evidence-retention path in `real-live-run` with an explicitly authorized `QA_EVIDENCE` root. Leave unrelated mock, import, packaging and security smoke tests unchanged. Check `getSettings.value.storageLocation` against the validated canonical library **after** launch as defense in depth; do not rely on `listMeetings` because hybrid lists can contain mock fixtures.

## Focused, silent acceptance tests

- **`scripts/m1-test-isolation.test.mjs` (new, Vitest):** invented temp fixtures. Valid sibling directories + pointer PASS. Missing pointer, invalid JSON, `{}`, `{root:""}`, relative root, pointer mismatch, missing library, file in place of directory, profile/library equal or nested, path outside allowed tree, default Documents library, **a retained `allowedRoot` nested under Documents/Meeting Scribe**, a retained parent containing an owner library, a moved/unknown owner library, symlink/junction escape (including a Windows junction alias into the owner library), and partial inputs all FAIL. Only letter-case differences pointing to the **same verified physical directory** are normalized; changing a path's actual target or an unprovable alias fails. Prove `SCRB_DEV_AUTO_LOCATION=1` cannot convert any failure to PASS; no owner paths are read.
- **`scripts/m1.test.sh` and `scripts/m1.test.ps1` (extend):** with all real-mode tool paths stubbed as valid, invoke the opt-in launcher with each bad pointer **and the nested-under-Documents retained-root fixture (plus a Windows junction alias)** and assert a **nonzero exit and no `npm` invocation or child Electron launch**. Valid pointer forwards the explicit `--user-data-dir` exactly; ordinary non-test mode retains established behavior. Keep existing `.cmd` forwarding unchanged.
- **Electron fixture tests:** with invented data, verify preflight happens before `electron.launch` and rejects broken pointers without opening a window. In an isolated successful launch verify actual backend `getSettings.storageLocation` equals expected root; **never** infer safety from the mixed mock/real Recordings list. Existing recording, final-pass and evidence-retention tests remain the downstream regression checks; do not run actual capture for this planning slice.

## Risks, exclusions, review gate

A broken guard could still reach real Documents; a too-strict guard could block legitimate retained public QA evidence; a caller-controlled `QA_EVIDENCE` root could otherwise authorize a nested owner-library path. Prevent both with the negative fixtures, explicit allowed-root mode and zero-child-process assertions. Do not modify `readLibraryLocation`, production fallback/recovery, production security, contracts, native capture, storage persistence, or existing owner data. This document is a proposed test-only slice, **not authorization to implement**. Require an independent plan review in a separate session; if it identifies a protected behavior change, obtain owner approval under the risky-change process **before** coding. Once scoped code is approved: targeted checks and exact-head macOS/Windows CI, then independent formal code review, then owner merge decision. No long physical test or private recording is needed.
