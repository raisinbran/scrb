# V1 microphone noise filtering and echo suppression — decision plan

**2026-11-25 · PLAN ONLY · No build, model run, audio capture or product change authorized.** Owner review, independent review and a separate native-audio approval precede implementation. This is V-b / V13, not an M1 acceptance claim.

## Problem and hard constraints

The [Mac B0 Teams result](../gates/m1-mac-b0-teams-run-results-20261124.md) found remote speech about **8 dB louder** on the mic track than the owner's own speech, with about **14 short duplicate "You" fragments**; [#487](https://github.com/raisinbran/scrb/issues/487) tracks this V1 gap. Presets are not functional merely because their Settings flags persist ([V1 input closure](v1-input-settings-closure.md); [V13 checklist](../acceptance/v1-installed-acceptance-checklist-20261122.md)). Keep both saved microphone and meeting originals unchanged, synchronized and continuously writable. No processing may alter other apps' actual playback or the separate meeting track. Recording takes priority over inference.

The prior [Apple voice-processing spike](mic-echo-spike-results.md) achieved **at least 15 dB mic echo reduction** but reduced the process-tap meeting track by **about 9 dB**, versus an existing **0.5 dB maximum**. That path was rejected for production; it remains opt-in only. Post-transcription dropRoomEcho in packages/transcription/src/finalPass.ts and LiveEchoFilter are text-level damage controls, **not** a replacement for audio echo cancellation.

## Options and decision (evidence, licence, limits)

| Option | What it actually does | Rights / source | Decision |
| --- | --- | --- | --- |
| **WebRTC Audio Processing Module (APM; AEC3 + noise suppression + gain)** | Adaptive acoustic echo cancellation with a **far-end/render reference**, denoise/AGC on 10 ms-class frames; CPU-focused, no large speech model | [WebRTC source BSD-style three-clause](https://webrtc.googlesource.com/src/+/refs/heads/main/LICENSE); audit vendored third-party notices | **Preferred on both platforms** on a separate recognition copy, subject to build size/CPU and reference alignment proof |
| **RNNoise** | Small RNN suppresses background noise, **not echo without an AEC reference** | [Xiph BSD-3-Clause](https://github.com/xiph/rnnoise/blob/main/COPYING) | Candidate for **Strong** noise reduction after AEC; measure doubled latency/near-field WER, no compulsory model download |
| **DeepFilterNet** | Full-band 48-kHz neural denoiser, heavier runtime than first choice; **not an AEC** | [Project MIT/Apache-2.0 statement](https://github.com/Rikorose/DeepFilterNet/blob/main/README.md) for code/weights; [checkpoint redistribution question](https://github.com/Rikorose/DeepFilterNet/issues/712) warrants pinned-artifact verification | Defer unless light filters miss quality bar; do not bundle unverified weights |
| **SpeexDSP echo canceller + preprocessor** | Adaptive echo + denoise, AGC, residual-echo suppression; older, simple native integration | [Xiph permissive BSD-style notice](https://github.com/xiph/speexdsp/blob/master/COPYING), [AEC interface](https://github.com/xiph/speexdsp/blob/master/include/speex/speex_echo.h) | **Cross-platform fallback** if WebRTC licensing/build/latency cannot meet limits |
| **macOS Voice Processing I/O / Mic Modes** | OS voice processing can suppress echo but couples to playback; may change saved mic path | [Apple Audio Unit Voice I/O](https://developer.apple.com/documentation/AudioToolbox/audio-unit-voice-i-o); project spike above | **Do not use as default**: measured meeting-tap attenuation fails; reconsider only after independently proving zero ducking and a separate raw original |
| **Windows communications / Voice Focus processing** | Endpoint/driver APOs or NPU-specific enhancement; capability varies with hardware and mode | [Windows modes](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/audio-signal-processing-modes), [Studio Effects](https://learn.microsoft.com/en-us/windows/apps/develop/windows-integration/studio-effects) | Detect and report only; not a universal dependency or evidence of an unprocessed saved input |

**Platform choice:** Mac: keep the raw HAL MicStream and process a fork with APM, using the captured meeting render as the initial echo reference; no Voice Processing I/O until its ducking failure is resolved. Windows: use the pre-APO/raw capture route when demonstrably available, write original packets first and feed a fork through APM; do not assume communications mode preserves raw. On either platform, use SpeexDSP for AEC + suppression if APM fails the build/performance proof. A tapped meeting app might **not** equal all sound emitted by the speaker; mark absent/incomplete far-end reference and disable AEC safely rather than silently promising cancellation. Do not reconfigure the user's playback or capture additional sources without separate consent/design review.

## Integration boundary and Settings mapping

- **Saved originals:** native/macos-capture/src/Capture.swift (MicStream / MeetingStream, rt.c), Chunks.swift; native/windows-capture/src/TrackPipeline.cpp writes through sink_.Write. Preserve these inputs, timestamp/gap rules and existing saved Opus; test same-input raw chunk bytes unchanged with processing off/on.
- **Live recognition fork:** Mac native/macos-capture/src/LiveFeed.swift receives a **separate live ring**; Windows TrackPipeline.cpp calls cfg_.live->Offer **after** saved sink_.Write, feeding native/windows-capture/src/LivePcmFeed.cpp. Apply AEC to the **microphone live copy only** using delayed/resampled meeting reference and bounded per-track queues; never stall saved writer. Keep frame metadata, clock generation and boundaries. apps/desktop/src/main/recording.ts opens the capture helper, apps/desktop/src/main/live-feed.ts decodes the live PCM pipe and offers frames to transcription. These are proposed insertion points, **not a currently implemented DSP path**.
- **Final pass:** packages/app-core/src/final-pass.ts supplies sealedTracks; packages/transcription/src/finalPass.ts decodes saved mic/meeting audio. Apply the same processing profile to decoded temporary **recognition-only** PCM before final mic Whisper inference, never rewrite sealed audio. Record profile/version for reproducible reprocess; if the far-end reference is lost, revert recognition only to raw and expose a truthful warning. Keep existing conservative dropRoomEcho as a backstop.
- **Off** = no noise suppression (echo cancellation independently configurable under Custom); **Standard** = APM denoise + tested AEC; **Strong** = APM AEC + RNNoise if it passes fidelity/latency gates, else explicitly unavailable (never pretend). **Voice Isolation** = Strong NS + AEC + bounded AGC enabled; **Studio** = bypass all recognition-copy enhancement; **Custom** = each saved switch determines actual behavior. Bypass system input processing means raw input where physically supported, not permission to change system settings. The UI must distinguish enabled, unavailable and failed modes. Use existing AudioSettings/presets and docs; **no contract changes are assumed**. A new UI event/type/mode requires a separate owner-approved packages/contracts/APPROVALS.md row.

## Quantitative gate (proposed, must be approved before tuning)

Use reproducible [public AMI](../research/outline-slice1-accuracy.md) speech (audio fixtures, not outline scoring) and invented near-/far-end clips, deterministic 40–400 ms echo delay, fixed room response/noise; test far-end-only, near-end-only, **double-talk**, quiet speech, device switch, pause/restart, and an **approved** speaker-playback bleed test on Mac/Windows with a separately measured physical output monitor. Record baseline source SHA/device/volume and paired raw/processed audio.

**Pass on each platform, including weakest machine:** near-field mic transcription WER **not greater than the unfiltered baseline** (pooled, percentage points); at least **12 dB far-end leakage reduction** in far-end-only windows and **8 dB** during double-talk while near-end words remain intact; at least **6 dB noise reduction** for Standard and **10 dB** for Strong on synthetic non-speech noise, with no worsened WER; false duplicate "You" fragments **at most 2 per 5-minute comparable B0 script**, down from about 14; no physical speaker-level change or meeting-track change exceeding **0.5 dB**. Added algorithmic live latency **<20 ms**, 10-ms-frame CPU processing **<5 ms p95**, no queue growth/broken live 3-s median / 6-s p95, unexplained audio gap **≤100 ms**, drift **≤50 ms**, no raw-file changes or dropped chunks. If a bar fails, do not enable that profile; report device-specific unavailability. Acoustic dB and WER bars are proposed design gates, **not measurements**.

## Independently reviewable slices / approval

1. **Offline experiment, ~8–12 h:** pin dependency commit/licences, implement pure PCM bench harness and public AMI/invented AEC/denoise test matrix, compare APM vs Speex; no app plumbing. Gate: reproducible metrics and bounded memory.
2. **Mac recognition fork, ~12–18 h:** raw-preserving copy in live/final paths behind OFF-by-default experiment switch, device/restart/clock tests. Requires **owner approval of native recording risk** and independent review before enabling.
3. **Windows recognition fork, ~12–18 h:** same invariant, Win11 raw/communications capability check and fallback; separate PR, no claim of universal APO behavior.
4. **Settings/profile + final parity, ~10–16 h:** wire existing controls honestly; no hidden model download. If a contract change is unavoidable, obtain approval and record an APPROVALS.md row **before** editing contracts.
5. **Installed V13/8-h integrity acceptance, ~8–12 h plus separately authorized long tests:** AMI and physical playback tests on identified release builds; maintain Gate 8 and output-ducking stop conditions. Target <=700 changed lines per review; use stacked slices if necessary.

**Total planning estimate: 50–76 engineering hours**, not a run authorization. Each source PR needs exact-head checks then independent formal review and owner merge authorization. No private meeting audio, device test, long run or dependency installation is authorized by this plan.
