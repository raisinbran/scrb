## 1. Import multiple audio files — medium, 2–3 days

**Today.** The [native chooser](../../apps/desktop/src/main/backend.ts) specifies `openFile` alone, takes only `filePaths[0]`, and supplies no `defaultPath`. The [coordinator](../../apps/desktop/src/main/imports.ts) issues expiring opaque file tokens and rejects a second start while it is starting, running, or recording. It sets `queued` on the single job before starting work. [LibraryView](../../apps/desktop/src/ui/screens/recordings/LibraryView.tsx), [ImportPanel](../../apps/desktop/src/ui/screens/recordings/ImportPanel.tsx), and the [tracker](../../apps/desktop/src/ui/screens/recordings/import-tracker.ts) show import entries and ask about building voice profiles per selection, default off each time. The retry currently reuses a token the backend has already consumed.

**Batch admission.** Use native `multiSelections`. Show the file count and one **Build voice profiles from these files** choice. It defaults to the user's last choice, which main remembers in userData and returns with the chooser response; at first launch it is off. Record the choice only when a batch is admitted. The remembered default is a preselection only: explicit confirmation of the visible choice is still required at enqueue. Preserve the existing consent rationale and current jurisdiction wording. Admit batches atomically in main, in picker order, with an initial cap of 16 waiting plus running items. Reject empty or oversized batches, duplicate tokens or canonical sources, tokens outside the current picker selection, stale or consumed tokens, and sources already queued or running. A rejected batch leaves jobs and token ownership untouched; a successful batch spends every token and binds the selected sources and consent to private in-memory jobs. Return one ID per file and publish all Queued rows before the first dispatch. Only basenames and opaque IDs cross the bridge.

**Privacy and reload.** Issue a main-owned policy snapshot with the chooser response and bind explicit opt-in to its revision at enqueue. Compute that revision from the current saved jurisdiction and effective rules, without exposing paths or private metadata. An unknown jurisdiction follows the conservative warning policy. At dispatch, recheck the source identity and policy under main ownership. A replaced or missing source fails its own item. For opted-in jobs, a different policy revision holds that item before any file processing and updates its reminder. The owner can reconfirm that item under the new policy, turn profile building off for it, or cancel it. A remembered default never substitutes for this reconfirmation, and a held item's choice does not change the remembered default. Preserve FIFO at a held head and show the reason. Recheck at the voice-write boundary as well. Hold a policy-write gate across the final revision check and any voice persistence or profile matching. Policy updates take the same gate. A policy change before that commit discards in-memory voices, suppresses profile matching and persists the meeting with `buildVoiceProfiles: false` before publishing ready, so ordinary Re-process cannot learn later without fresh consent. If that safe commit fails, fail the item and use staging recovery. A policy update after a completed voice commit applies to subsequent work, subject to the existing purge controls. Dismissal hides only that item's reminder for its current policy revision until termination; it does not consent, clear a hold or affect another item. Main owns all state. Load a revisioned queue snapshot on renderer startup and use full snapshots on change. Apply only the latest revision to resolve event/response races.

**Scheduling and interruption.** One FIFO worker. Use a shared main-process admission fence for the import and voice coordinators. Recording Start or approved quit closes both in one synchronous transition before the first await. Dispatch checks the hold and claims the running ID in the same transition. The recording path aborts the owned running item and awaits its cleanup or bounded worker termination. A pre-commit interruption is terminal, with fresh selection and consent required to retry. A completed commit remains success. Queued items stay paused through capture and stop cleanup. Release the hold only on confirmed idle, including a failed or cancelled Start after its cleanup. Task completion releases only its own job slot and passes through the same dispatch gate. Quitting while an import is running or waiting first shows a short confirmation dialog: one sentence, **Cancel** and **Quit** buttons. A quit with no import work shows no new dialog. For approved quit, enter irreversible closing before awaiting any shutdown hooks, reject admission, terminally cancel waiting items, invalidate picker tokens and drain the owned active job. A cancelled quit prompt leaves the queue unchanged. Include the dispatch state in each snapshot so waiting rows can explain recording, closing or cleanup holds. Keep existing staging recovery; unclear cleanup blocks dispatch and surfaces a recovery message. The queue is memory-only. Normal failures and cancels affect only their own item. Each accepted ID gets one terminal result. Keep the 32 most recent terminal results in the in-memory snapshot so reload can restore them; only waiting and running items count against the queue cap. Retry is a new tail entry that needs fresh confirmation; the choice is preselected from the remembered last choice.

**Files and contract.** Desktop main `backend.ts`, `imports.ts` and recording/quit coordination; Recordings files above; mock/hybrid routing; contract members below. Reuse existing per-item terminal events and extend success with the profile outcome.

**Tests.** Chooser and all-or-none admission, remembered last choice (first launch off, updated only on admission), token bounds and duplicates, immediate rows and FIFO, reload and out-of-order snapshots, warning dismissal and policy changes before dispatch and persistence, source replacement, per-file failure/cancel/retry, simultaneous Start and completion, failed Start, Stop through cleanup, quit dialog wording and Cancel/Quit paths with and without import work, cancelled and approved quit, stale callbacks after closing, bounded drain and recovery.
