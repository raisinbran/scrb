# Import and export polish

Source reviewed at `e6aa2fdd`. This plan proposes future changes and requires independent review before owner approval.

## 1. Import multiple audio files — medium, 2–3 days

**Today.** The [native chooser](../../apps/desktop/src/main/backend.ts) specifies `openFile` alone, takes only `filePaths[0]`, and supplies no `defaultPath`. The [coordinator](../../apps/desktop/src/main/imports.ts) issues expiring opaque file tokens and rejects a second start while it is starting, running, or recording. It sets `queued` on the single job before starting work. [LibraryView](../../apps/desktop/src/ui/screens/recordings/LibraryView.tsx), [ImportPanel](../../apps/desktop/src/ui/screens/recordings/ImportPanel.tsx), and the [tracker](../../apps/desktop/src/ui/screens/recordings/import-tracker.ts) show import entries and ask about building voice profiles per selection, default off. The retry currently reuses a token the backend has already consumed.

**Proposal and design.** Add native `multiSelections` for the same audio formats. Show one confirmation with the selected file count and one **Build voice profiles from these files** choice, reset to off each time. Keep the existing consent rationale and jurisdiction reminder. On confirmation, validate and reserve the whole batch, allocate one ID per file, and publish every Queued row in Recordings before dispatching the first job. Queue rows are import entries until completion produces meetings. Keep one model-heavy worker and FIFO order across batches. Make the token cap batch-aware and disclose any selection limit before enqueueing. Pass basenames and opaque IDs across the bridge. Revalidate source availability on dispatch, with a missing file failing only its own row.

**Lifecycle and risks.** Cancel a queued item immediately. Cancel a running item through the existing abort and cleanup path, preserving a successful commit if cancellation arrives too late. Advance only when the previous job has settled. A normal failure leaves siblings in place. For uncertain staging cleanup, stop dispatch and show a queue-wide recovery message. A retry asks the owner to choose the file again, reconfirms the previous consent choice with off as the fresh default, and appends a new attempt at the tail. Preserve recording priority by pausing dispatch and using existing active-import interruption. Resume after recording is idle. The queue is memory-only, visible across navigation through `listImports`, and cleared on shutdown. Keep existing startup staging recovery. Prevent duplicate terminal events and handle events arriving before the batch response.

**Files and contract.** Desktop main `backend.ts` and `imports.ts`, Recordings files above, mock/hybrid backend, contract call map and validators. Replace `pickAudioFile` with `pickAudioFiles` and `importAudioFile` with `importAudioFiles` as specified below. Extend `cancelImport.request.importId` eligibility and `listImports.response` semantics. Reuse existing stages and per-job events.

**Tests.** Native chooser options and token bounds; 3 immediate queue rows; serial FIFO across navigation and response/event races; middle-job cancel and failure; expired token and retry; recording preemption/resume and shutdown cleanup; batch privacy off/on; installed short invented-audio check with unchanged source bytes.

## 2. Build voice profiles later — large, 3–5 days

**Today.** [Imports](../../apps/desktop/src/main/imports.ts) persist opt-in in [meeting metadata](../../packages/storage/src/formats/meeting.ts). [saveFinalVoices](../../packages/app-core/src/voices.ts) requires that flag and the approved embedding model, excludes You, and writes meeting-scoped `voices.json` from final-pass embeddings. The imported-meeting UI has no later opt-in. [Re-process](../../apps/desktop/src/main/meetings.ts) (`retryFinalPass`) reruns recognition and diarization on saved sealed audio under the existing flag. [Final-pass application](../../packages/app-core/src/final-pass.ts) reapplies compatible corrections and refreshes voice data for eligible meetings. It can make the summary stale.

**Proposal and design.** Put **Build voice profiles** in the meeting detail action row near Re-process, using the existing dialog and privacy wording. Show it on eligible imported meetings with saved audio and no completed opt-in; render busy/failed feedback on that meeting. Require explicit consent for each attempt. Add a dedicated backend action that extracts approved-model embeddings from trustworthy saved audio spans assigned to current speaker IDs. Reuse the sealed-audio preparation and Sherpa embedding path in [finalPass.ts](../../packages/transcription/src/finalPass.ts) and [sherpa.ts](../../packages/transcription/src/sherpa.ts). Use the existing model gate. Keep transcript words, names, timestamps and summary state intact. Report insufficient eligible audio rather than building from uncertain, split, overridden or unresolved assignments. Keep ordinary Re-process independent of opt-in. After a successful opt-in it may refresh voice data through its existing flow.

**Contributions, retention and risks.** Follow [voice-profile growth](voice-profile-growth.md). Existing hand-named, linked speakers use normal reconciliation; unlinked names contribute only via the approved rename-learning rules and quality gates. Auto-links and You never teach a profile. Save approved-model voices only, reconcile under the established global profile lock followed by the meeting lock, and persist `buildVoiceProfiles` only on successful completion. Stage output first, revalidate transcript revision, audio and job ownership at commit, and define rollback/recovery for a partial write. Reuse purge paths in [Library](../../packages/storage/src/library.ts). Manual audio deletion, audio-only retention and whole-meeting deletion remove this meeting’s voices and contributions, then recompute surviving profiles. A race with deletion must never recreate purged data; missing, deleted or unreadable sealed audio blocks the action. Do not export embeddings or change retention policy.

**Files and contract.** Desktop `MeetingDetailView.tsx` and `meetings.ts`; app-core `voices.ts` and model scheduling; transcription sealed-audio preparation and `sherpa.ts`; storage `library.ts` and existing voice reconciliation. Add `MeetingDetail.buildVoiceProfiles` and `buildMeetingVoiceProfiles` as below; keep existing storage metadata schema.

**Tests.** Existing import off and later consent/cancel; duplicate requests; approved-model and minimum-evidence gates; named versus auto-linked speakers; no transcript or summary change; write failure/retry, stale revision, delete/retention race and shared-profile recomputation. Use invented fixtures and synthetic vectors.

## 3. Remember folders by action — small, 0.5–1 day

**Today.** [Export handlers](../../apps/desktop/src/main/export.ts) use one userData `export-location.json` configured in [backend.ts](../../apps/desktop/src/main/backend.ts). [export-location.ts](../../apps/desktop/src/main/export-location.ts) accepts absolute existing directories; a successful write updates the remembered folder. The import chooser has no remembered folder. The [V-j runbook](../runbooks/v-j-import-formats.md) and [call map](../../packages/contracts/src/backend.ts) cover audio import only. No notes or transcript import exists. Opening the meeting's audio folder and playing audio are available; no native audio-export command exists in this checkout.

**Proposal and design.** Keep the existing file/key for document exports to preserve the current default. Reuse the same helper for a separate userData audio-import location file, updating it after the picker returns a valid selection. For a cross-directory selection, remember the first accepted file’s parent. Reserve a separate audio-export location file for the slice that introduces audio export. Notes/transcript import gets a separate slot if that feature is added. A missing, unplugged, invalid or inaccessible directory falls back to the existing in-library export folder for document export and the system chooser default for import. Treat the path as a dialog hint, preserve validation and atomic output replacement at the destination, and do not alter preferences on picker cancellation or failed export.

**Files, contract and tests.** Desktop `export-location.ts`, `export.ts`, `backend.ts` and their tests. No contract change for location memory. Test persistence across restart, slot independence, previous preference compatibility, invalid/unmounted paths, cancellation, save failure, and a disappearing destination after picker confirmation.

## 4. Speaker initials in exported notes — medium, 1–2 days

**Today.** [ExportDialog](../../apps/desktop/src/ui/screens/recordings/ExportDialog.tsx) has a speaker-names visibility toggle. The desktop [export handler](../../apps/desktop/src/main/export.ts) takes a common [app-core export projection](../../packages/app-core/src/export-summary.ts) into DOCX/PDF and transcript-only VTT. Desktop Markdown export does not exist. [Clipboard copy](../../apps/desktop/src/ui/screens/recordings/copy-transcript.ts) independently formats the loaded transcript with full labels. Summary action owners are stored as strings.

**Proposal and design.** Add a persistent **Speaker names** choice in Settings → Export, with **Full names** recommended as the default pending owner decision. The export dialog retains its existing show/hide toggle. Read the saved style at the start of export and copy. Apply one backend presentation map keyed by speaker ID before format-specific rendering. Use the first Unicode letter of each whitespace-separated word of a multiword name, uppercased. Keep one-word names, unnamed labels and You as displayed. Number colliding initials by first transcript occurrence, with speaker ID as a stable tie-break, and reserve unchanged labels to prevent secondary collisions. Use the same map on structured summary attribution only where an owner exactly and uniquely matches a named speaker; preserve ambiguous owners, prose, quotations and source text. Apply the map when a Markdown export is later added. Preserve full names in the app and settings persistence. Initials are a presentation preference, and names may still occur in prose.

**Files and contract.** Settings UI and [app-core settings](../../packages/app-core/src/settings.ts), storage settings adapter, app-core export projection plus common label mapper, desktop export and meeting handlers, and `CopyTranscriptAction.tsx`. Route copy formatting through `getTranscriptCopyText`, preserving readiness, ordering and clipboard feedback. No new renderer clipboard privilege. Add the saved setting and copy call below. `ExportRequest` needs no field because the preference applies consistently to export and copy.

**Tests.** Full-name default and older settings; Unicode, single-word, unnamed, You, collisions and ambiguous owners; visibility off; exact label parity in DOCX/PDF/VTT and copy, with invented read-back fixtures; original transcript and app labels intact.
