# Import and export polish

Source reviewed at `e6aa2fdd`. This plan proposes future changes and requires independent review before owner approval.

## 1. Import multiple audio files — medium, 2–3 days

**Today.** The [native chooser](../../apps/desktop/src/main/backend.ts) specifies `openFile` alone, takes only `filePaths[0]`, and supplies no `defaultPath`. The [coordinator](../../apps/desktop/src/main/imports.ts) issues expiring opaque file tokens and rejects a second start while it is starting, running, or recording. It sets `queued` on the single job before starting work. [LibraryView](../../apps/desktop/src/ui/screens/recordings/LibraryView.tsx), [ImportPanel](../../apps/desktop/src/ui/screens/recordings/ImportPanel.tsx), and the [tracker](../../apps/desktop/src/ui/screens/recordings/import-tracker.ts) show import entries and ask about building voice profiles per selection, default off. The retry currently reuses a token the backend has already consumed.

**Batch admission.** Use native `multiSelections`. Show the file count and one **Build voice profiles from these files** choice, reset to off each time. Preserve the existing consent rationale and current jurisdiction wording. Admit batches atomically in main, in picker order, with an initial cap of 16 waiting plus running items. Reject empty or oversized batches, duplicate tokens or canonical sources, tokens outside the current picker selection, stale or consumed tokens, and sources already queued or running. A rejected batch leaves jobs and token ownership untouched; a successful batch spends every token and binds the selected sources and consent to private in-memory jobs. Return one ID per file and publish all Queued rows before the first dispatch. Only basenames and opaque IDs cross the bridge.

**Privacy and reload.** Issue a main-owned policy snapshot with the chooser response and bind explicit opt-in to its revision at enqueue. Compute that revision from the current saved jurisdiction and effective rules, without exposing paths or private metadata. An unknown jurisdiction follows the conservative warning policy. At dispatch, recheck the source identity and policy under main ownership. A replaced or missing source fails its own item. For opted-in jobs, a different policy revision holds that item before any file processing and updates its reminder. The owner can reconfirm that item under the new policy, turn profile building off for it, or cancel it. Preserve FIFO at a held head and show the reason. Recheck at the voice-write boundary as well. Hold a policy-write gate across the final revision check and any voice persistence or profile matching. Policy updates take the same gate. A policy change before that commit discards in-memory voices, suppresses profile matching and persists the meeting with `buildVoiceProfiles: false` before publishing ready, so ordinary Re-process cannot learn later without fresh consent. If that safe commit fails, fail the item and use staging recovery. A policy update after a completed voice commit applies to subsequent work, subject to the existing purge controls. Dismissal hides only that item's reminder for its current policy revision until termination; it does not consent, clear a hold or affect another item. Main owns all state. Load a revisioned queue snapshot on renderer startup and use full snapshots on change. Apply only the latest revision to resolve event/response races.

**Scheduling and interruption.** One FIFO worker. Use a shared main-process admission fence for the import and voice coordinators. Recording Start or approved quit closes both in one synchronous transition before the first await. Dispatch checks the hold and claims the running ID in the same transition. The recording path aborts the owned running item and awaits its cleanup or bounded worker termination. A pre-commit interruption is terminal, with fresh selection and consent required to retry. A completed commit remains success. Queued items stay paused through capture and stop cleanup. Release the hold only on confirmed idle, including a failed or cancelled Start after its cleanup. Task completion releases only its own job slot and passes through the same dispatch gate. For approved quit, enter irreversible closing before awaiting any shutdown hooks, reject admission, terminally cancel waiting items, invalidate picker tokens and drain the owned active job. A cancelled quit prompt leaves the queue unchanged. Include the dispatch state in each snapshot so waiting rows can explain recording, closing or cleanup holds. Keep existing staging recovery; unclear cleanup blocks dispatch and surfaces a recovery message. The queue is memory-only. Normal failures and cancels affect only their own item. Each accepted ID gets one terminal result. Keep the 32 most recent terminal results in the in-memory snapshot so reload can restore them; only waiting and running items count against the queue cap. Retry is a new tail entry and defaults to consent off.

**Files and contract.** Desktop main `backend.ts`, `imports.ts` and recording/quit coordination; Recordings files above; mock/hybrid routing; contract members below. Reuse existing per-item terminal events and extend success with the profile outcome.

**Tests.** Chooser and all-or-none admission, token bounds and duplicates, immediate rows and FIFO, reload and out-of-order snapshots, warning dismissal and policy changes before dispatch and persistence, source replacement, per-file failure/cancel/retry, simultaneous Start and completion, failed Start, Stop through cleanup, cancelled and approved quit, stale callbacks after closing, bounded drain and recovery. Use deterministic scheduler barriers and short invented fixtures.

## 2. Build voice profiles later — large, 5–8 days

**Today.** [Imports](../../apps/desktop/src/main/imports.ts) persist opt-in in [meeting metadata](../../packages/storage/src/formats/meeting.ts). [saveFinalVoices](../../packages/app-core/src/voices.ts) requires that flag and the approved embedding model, excludes You, and writes meeting-scoped `voices.json` from final-pass embeddings. The imported-meeting UI has no later opt-in. [Re-process](../../apps/desktop/src/main/meetings.ts) (`retryFinalPass`) reruns recognition and diarization on saved sealed audio under the existing flag. [Final-pass application](../../packages/app-core/src/final-pass.ts) reapplies compatible corrections and refreshes voice data for eligible meetings. It can make the summary stale.

**Consent and job.** Put **Build voice profiles** near Re-process on eligible imported meetings with saved audio and no prior opt-in. Main issues a short-lived, single-use prompt token bound to meeting, saved-audio generation, transcript revision and current jurisdiction policy. Use the existing consent wording and conservative warning for unknown jurisdiction. Start requires explicit confirmation and the matching token. Check the policy and eligibility at start and commit; stale consent fails closed and requires a new prompt. Show a main-owned job with stages and cancellation. Use one job per library, exact job IDs, query plus versioned events, and retain its latest terminal state in memory until the next attempt or reload of the backend. Renderer reload restores the job from main. App restart resolves the durable outcome from storage and never silently restarts inference.

**Execution and ownership.** Use trustworthy spans from the current transcript and sealed audio with the approved Sherpa embedding model and the existing minimum-evidence gates. Exclude You, auto-linked learning, and ambiguous, split, overridden or unresolved evidence. Reuse the model gate and register the job immediately with existing critical-activity/quit protection. Reject starts during recording or shutdown. Recording Start and approved quit close admission before awaiting work, abort only the owned precommit job (including model-gate wait), and drain it through bounded worker termination. Start proceeds after settlement. Hold the commit section briefly and make it non-cancellable once the storage transaction begins. On timeout without verified termination, revoke commit authority and preserve the existing protected shutdown/cleanup behavior. Cancellation before commit writes no voice data. A late cancel returns the committed outcome. Terminal settlement clears critical activity exactly once.

**Durable privacy boundary.** Use one SQLite transaction for late opt-in, approved-model voice rows, this meeting's contribution updates and affected profile aggregates. Keep extracted vectors in memory until the transaction. Do not write a staging `voices.json`. Add a meeting-keyed row for the accepted late opt-in and its active voice set. Readers and reconciliation consult only committed rows for late-opt-in meetings, and expose the effective flag through meeting detail. Keep the existing metadata flag and `voices.json` path for legacy/import-time opt-ins. Under global profile lock then meeting lock, use an internal non-reentrant helper to recheck ownership, saved audio, transcript revision, policy, and the absence of conflicting legacy voice artifacts. Update only eligible existing hand-named links and their contributions; preserve unrelated rows and plain links. Use SQLite rollback on error or crash before commit; after commit the opt-in and voices are both visible and a lost response is recovered from the effective flag. No application journal spans a database and filesystem commit. [Index upgrade snapshots](../../packages/storage/src/db/database.ts) currently use `VACUUM INTO`. Before enabling late opt-in, switch snapshot creation for the new schema to a logical copy from one consistent read transaction into a fresh restricted file. Allowlist non-voice data and preserve profile identity, display names and plain links. Omit all voice vectors, contribution payloads and derived aggregates, plus the late authorization rows. Represent preserved profiles without a vector as ineligible for matching until fresh approved evidence exists. Verify the snapshot against that redacted projection before publishing it. Creating a full temporary copy and redacting it afterward would leave a crash window. Keep this recovery snapshot out of meeting exports.

**Retention and transcript behavior.** Keep words, names, timestamps, transcript revision and summary unchanged. Unlinked speakers can acquire profiles later via an explicit rename using the existing approved learning rules. Show the counts saved and contributed so zero linked contributions is clear. Ordinary Re-process never opts a meeting in. For committed late opt-ins, future voice replacement uses the same transactional store and existing final-pass reconciliation rules; it cannot switch back to legacy voice files. Integrate all audio and meeting purge routes. Purge the late voices and contributions before deleting audio, recompute surviving profile aggregates, and fail closed if purge fails. When no contribution survives, clear the saved aggregate vector and sample count and make the profile ineligible for matching, even if a kept name or plain link survives. Invalidate undo/redo snapshots that could restore purged contributions. Keep the live database and its recovery files within existing restricted library access. A deletion reservation invalidates precommit jobs and prevents re-creation; committed data is purged by the existing deletion owner. Recover a crash during deletion without restoring voices or retrying learning. Restoring a redacted snapshot never restores late authorization or vectors. Repair against the authoritative meeting files and reject any recovered link contribution without presently saved audio and eligible current voice evidence. A retained older snapshot that can contain vector data must be resolved and removed through the existing index-recovery flow before enabling the feature; if it cannot be removed, fail closed. The new redacted snapshot can preserve user-visible profile names but cannot restore voice evidence after index loss. Preserve existing legacy-file cleanup semantics. Follow the [voice-growth rules](voice-profile-growth.md) and the purge sequence in [Library](../../packages/storage/src/library.ts).

**Files, contract and tests.** Desktop meeting detail, coordinator, recording/quit hooks and mocks; app-core voice extraction/scheduling; transcription sealed-audio and Sherpa embedding helpers; storage migration, effective consent, voice readers, reconciliation, purge, and index snapshot/recovery. Add job lifecycle members below. Test stale prompt and revision, cancel during gate wait and extraction, late cancel, renderer and app restart, Start/quit barriers, worker timeout, pre/postcommit crash injection, duplicate requests, low evidence and human-naming gates, preservation of legacy and unrelated profile data, redacted snapshot verification, interrupted snapshot creation and restore after audio purge, and every delete/retention ordering including purge fail-closed and the last contribution on kept and plain-linked profiles. Use synthetic vectors and invented audio.

**Proposal and data.** Use the same keyboard-searchable country combobox in onboarding and Settings. Main provides a versioned policy catalogue. Show a second searchable region combobox only for countries marked region-required. Changing country clears the previous region. Save uppercase ISO 3166-1 alpha-2 `country` and nullable ISO 3166-2 `regionCode` (for example, `US-IL`). Validate the pair in main against the catalogue, including region ownership, and save location as a single replacement. For unknown locations, offer an explicit **Not sure** choice with a persistent generic reminder. Use `ZZ` for that country choice and null only for incomplete onboarding. Never infer consent from OS locale.

**Region catalogue is an owner/legal decision.** Propose **US only** for the first release, because the existing product already evaluates its states separately for the voice-profile privacy reminder. Include all supported US subdivisions in the input catalogue independently of their reminder status. Consider Canada and Australia for policy review if verified subnational privacy or recording-consent differences would change the app's reminder for the intended use. Enable region selection elsewhere only after the owner approves a vetted rule table. This is a product design proposal. It makes no determination about applicable law or whether recording is permitted.

**Eligibility, migration and dev setup.** Keep current listed-country and listed-state reminders as a floor, including existing library-specific positive rules. Evaluate country-wide and region-specific warnings together. For unknown, unlisted, missing-required-region, or unreadable policy data, show the conservative reminder. Only an explicit approved policy entry can suppress it. Use one main-side result for the Settings preview, live recording and opted-in import/late voice builds. Include policy and location revisions in the consent checks from sections 1–2. Keep the reminder advisory and preserve its existing per-recording dismissal lifetime.

Normalize legacy settings before strict request validation so unrelated preferences survive. Convert valid US `usState` to `US-*`; preserve valid explicitly saved non-US countries. Keep legacy `ZZ` as unknown and mark it unconfirmed in stored migration metadata. A new explicit Not sure save clears that marker. Derive `locationSet` from confirmation and valid selection, so legacy users are asked once on the next normal onboarding opportunity. Use OS locale only as an optional uncommitted suggestion. Unresolved records keep the conservative reminder during migration. Preserve the zero-interaction [development path](../../apps/desktop/src/main/synthetic-location.ts): only an unpackaged run with the flag, explicit temporary user-data directory and separate temporary library pointer may seed a fictional approved US subdivision through the settings handler before first window. Respect any existing saved location, including migrated records. Never automate the dialog.

**Files, contract and tests.** Desktop location dialog, Settings, `backend.ts`, `setup-status.ts`, `synthetic-location.ts`, mocks and hybrid routing; app-core `settings.ts` and `privacy.ts`; contract members below. Test searchable keyboard interactions, hidden/required region, country changes, legacy US/ZZ migration and retention of unrelated settings, unknown and unlisted cases, invalid/mismatched region, corrupt policy, all prior positive reminders, policy changes at consent time, and the development isolation checks.
