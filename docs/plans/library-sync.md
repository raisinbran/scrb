# Optional library sync between computers

**Status:** proposed, 2026-11-27; base `bfb61ebf`. Post-M1. Owner approval and independent storage/recovery design review required before implementation, especially any change to the voice store. Scope: one user's two authorized devices, not a shared team library or real-time collaboration.

## 2. Source baseline and failure modes

- Today the library location can point at a synced folder: `packages/storage/src/library.ts` reads/writes the local `library-location.json` pointer and opens the selected root. Help explicitly warns that a chosen cloud folder may be uploaded by that provider. At this SHA the real backend lacks the storage picker/move handler and Settings disables Change location; do not claim a supported in-app migration or tested two-computer sync. The shared-library notice concerns other local users, not distributed ownership. See [library move plan](task-16-library-move.md).
- `packages/storage/src/layout.ts`: one `index.sqlite` holds settings, vocabulary, profile embeddings, contributions, meeting links and deletion state. Meetings have metadata, transcript, summary, suggestions, `voices.json`, audio chunks/manifests and exports. Models, logs and cache live alongside them. `db/database.ts` intentionally uses rollback journal DELETE, FULL synchronous, foreign keys and secure_delete (not WAL). This helps local durability, not independent replicas. Concurrent cloud copies of DB/journal can lose committed rows, corrupt data or resurrect deletions. [SQLite guidance](https://sqlite.org/useovernet.html) also warns against multi-host filesystem locking.
- `library.ts` uses an in-process lock map (global voice-profile assignments lock before meeting lock); audio writer markers, process single-instance guards and atomic rename are local protections, not distributed leases. Startup reconciliation could misinterpret unavailable/half-synced meeting folders as lost. Provider conflict copies, reordered uploads, placeholders and offline edits break these assumptions.

**Recommendation:** keep a complete working library and SQLite index local on each device, outside all synced folders. Use a separate user-chosen synced folder only as a transport for versioned immutable records and, later, completed meeting bundles. No direct cloud API, provider credentials, live DB, rollback journal, index backup, active audio, log, cache, model or voice-file directory in transport. Do not silently migrate existing cloud-folder libraries: offer reviewed copy/verify/switch procedure with rollback; refuse sync until both working roots are local and distinct. Existing user copies remain under user control.

## 3. Stage 1: small, merge-friendly records

Settings → Sync (off by default) → choose a dedicated folder using native picker, choose categories, preview first reconciliation, pair second device with an owner-confirmed random library/sync ID and device IDs. Reject other-user roots, overlapping library, symlinks/junctions, incompatible schema and unexpected files. Use same-user devices only, private cloud ACL and encryption. Sensitive payloads (vocabulary, profiles and later meeting bundles) require authenticated client-side encryption; use reviewed established AEAD/key derivation with per-record unique nonce, key exchange via owner-held recovery secret, keys in local OS credential store. No keys or private text in filenames/logs. Review key rotation/loss/revocation and backup leakage; do not ship biometric sync without encryption. Settings records can use same encrypted format.

Local durable outbox: commit mutation plus operation ID in a transactional journal (or reviewed crash-safe equivalent), then write immutable per-device sequence records with schema, stable entity ID, causal parent/revision, operation kind and authenticated integrity. Sync imports are idempotent and checkpointed transactionally; never replay a mutation twice or re-export imported mutations. Compare causal history, not filesystem time/clock. Merge independent edits; missing file never means delete. Out-of-order dependencies wait, conflicts persist until explicit resolution. A complete initial snapshot is versioned, verified and imported with the same rules; no raw database copy. Limit sizes/counts, reject unknown schemas without overwriting originals. App status distinguishes local saved, pending provider transfer, remote applied (only verified peer acknowledgement), conflict, offline, blocked. Last good local state works without network; no “synced” solely from successful local write.

| Category | Merge / conflict rule |
| --- | --- |
| Settings (1a) | Whitelist cosmetic/user preferences (theme, transcript font, summary length) per key; unrelated changes merge, simultaneous differing values require choice. Keep audio device IDs/routes, hardware quality, location, paths, consent and crash preferences local. Auto-delete stays local initially; never import an enabled destructive setting without explicit owner choice. |
| Vocabulary (1a) | Stable term ID plus existing NFC/case/space normalization; combine independent additions and set additions, preserve explicit removals with tombstones. Conflicting rename, enable/disable, same normalized term with different identities, or conflicting variants prompt review; deletion wins over stale changes, no silent resurrection. First scope manually entered/preserved terms and variants only; context-linked learned terms, correction IDs and auto-learn provenance stay local until source-aware invalidation/undo and delete propagation are approved. Clearly show excluded learned data. |
| Speaker profiles (1b, separately opted in) | Stable profile ID, approved model ID/dimension, name, count, exact revision; never match/merge by name alone or average two aggregates (may double count). Start with a designated authoritative device per profile; other device may match a read-only imported profile and record local proposals but not grow/merge/rename it silently. Authority edits produce versioned encrypted replacements. Concurrent forks are quarantined, not applied; no offline authority transfer. Later multi-device growth requires a reviewed ledger of distinct origin contribution IDs and exact-once recomputation, not in first release. Delete/revocation supersedes stale updates and prevents re-learning from retired sources. |

Current vocabulary store has source/context tables and normalized deletion/dismissal keys; do not turn learned values into permanent manual ones. Voice store has per-meeting contribution rows, model IDs, weighted means, undo snapshots, FK links and per-meeting `voices.json` (explicitly not exported/backed up). See [voice profile growth](voice-profile-growth.md) and [index recovery](index-recovery.md). **Design gate:** review imported profile storage separately from source-meeting FKs (remote meeting may be absent). Track opaque origin/provenance and authoritative contribution/deletion revision; imported data cannot be treated as orphan or teach another aggregate. Integrate local matching read-only; no bypass of profile lock, reconciliation, unlink, undo or purge. If a source contribution is removed or audio-only deletion occurs, authority recomputes and publishes replacement/tombstone; recipients remove invalid contributions before reuse. Do not export raw `voices.json`, meeting names or audio. If exact deletion/reconciliation cannot be demonstrated, leave 1b off; settings/vocabulary may ship independently.

Consent UI (per device, separately for vocabulary, voice profiles and recordings): “Sync selected data using the folder you choose. Your cloud provider copies these files to its servers and your other authorized devices. Scribe does not operate that cloud service.” For voices, unchecked by default: “Speaker profiles contain biometric voice measurements and names used to recognize people. Sync encrypted profiles to my other authorized device. I have permission to store and share these profiles. Turning this off stops future syncing; previously synced copies and provider backups may remain until removed.” Explain provider access, recovery key, permitted use and applicable consent requirements; existing local profiling consent/banner is **not** sync consent. Disabling stops transfer; offer explicit remove-remote-data workflow with device acknowledgements; do not imply remote erasure while offline. Update Help/About/manual privacy language before enabling.

## 4. Files On-Demand, atomicity and stage 2

[OneDrive Windows](https://support.microsoft.com/en-gb/onedrive/save-disk-space-with-onedrive-files-on-demand-for-windows), [macOS](https://support.microsoft.com/en-us/onedrive/fix-onedrive-files-on-demand-issues-on-macos-12-1-or-later): require “Always keep on this device” for the transport directory on both devices; macOS Files On-Demand cannot simply be disabled. Detect offline/unreadable placeholder or pending hydration, no blocking capture and no interpreting zero-size/missing content as deletion; bounded retry, display actionable status. Windows antivirus/provider locks (EPERM/EBUSY/EACCES), quota, disconnect, permission errors and partial transfers retain local outbox and old valid data. Never overwrite or force-remove conflict copies; inspect and quarantine. Validate directory/file handles and size/hash/authentication on each read; do not follow links. Reuse `atomic.ts` same-directory exclusive temp, flush, rename, directory flush where supported and bounded Windows retries. Provider may expose temp or manifest before payload: import only verified committed records, ignore temp files, do not rely on rename/upload ordering across machines. Cleanup only own proven staging files. Persist applied IDs and retry state across restart.

**Stage 2, later approval:** two devices may record simultaneously into their separate local libraries, each with globally unique meeting ID and permanent origin writer. Only publish stopped, finalized, verified immutable bundles: sanitized opaque names, versioned manifest, content hashes, complete audio chunks and transcript/summary, encrypted, staged and verified before import into the other local library/index. No live sync, no copying DB, no profile voice files/logs/cache by default. Receiving device can play/read; only the origin may edit/reprocess/delete or publish new revision, including transcript corrections. Remote edit requests must be sent to origin, not applied locally. A lockfile/cloud folder timestamp cannot prevent split brain; no automatic lease expiry or offline takeover. Authority transfer deferred pending explicit protocol with both devices quiesced and acknowledged handoff; if origin is lost, preserve read-only copy and explicitly fork with new ID rather than assume ownership. Unexpected competing revisions block import and preserve both. Recording on A must never block B; concurrent editing of the same recording is not supported.

## 5. Deletion, recovery and verification

Deletion is a causal tombstone, not directory disappearance; owner confirms scope and authority. Distinguish unlink/disable sync, remove local copy, and delete on all devices. Origin handles active-job protection and whole-meeting vs audio-only retention using existing library deletion rules; propagate deletion of audio/voices and learned contributions as applicable; preserve text on audio-only deletion. Apply tombstone before old payload, persist across restart and backup restore; stale device must resync tombstones before publishing. Remove app-owned local/transport copies only after verified application and acknowledgements, keep non-sensitive tombstone ID/revision until all paired devices have acknowledged or are formally revoked and forced to re-pair from fresh state. Plan reviewed compaction of superseded encrypted records (especially biometric revisions); no indefinite sensitive history by default. Remote provider recycle bins, snapshots, user copies and offline devices may retain content; never claim physical/global erasure. Retention remains Never by default; no automatic delete of synced data on receiving device. Preserve ambiguous/sole valid copies per index recovery; no destructive auto-restore.

[Gate evidence policy](../gates/evidence-retention-policy.md) is separate from end-user retention: test recordings, both audio tracks/manifests, live/final transcripts and diagnostics remain private outside Git and cloud transport unless owner approves specific verified movement. No automatic teardown deletion, even on failure/pass; cleanup only after applicable gate passes and explicit owner authorization, preserve unresolved/later-gate evidence. Disposable invented unit fixtures may be cleaned; preserve substantive test evidence.

Automated tests: duplicate/reordered/missing operations, clock skew, concurrent same/different-key writes, Unicode term identity, delete-vs-edit and stale-device rejoin, bad ciphertext/key/schema, malicious paths/links, lock/quota/hydration and interrupted write/import/ack at each boundary; restart preserves local DB integrity and outbox. Voice tests: model/dimension mismatch, contribution removal/undo/reprocess/merge/rename, source missing, same-name different voices, profile tombstone vs offline learning; no resurrection or accidental FK cascade. Stage 2: incomplete manifest, two origins recording, conflict revision, origin loss, partial delete, recovery. Use invented/AMI only, isolated profiles and separate libraries.

**Manual two-computer checklist (Windows + Mac, same release):** (1) create two disposable local libraries and dedicated OneDrive test directory, pin on both; verify default off and no unauthorized files; (2) pair, consent to each category separately, verify only selected data appears; (3) change different keys/terms on both offline then reconnect; verify merges, same-key conflict review and deletion winning over stale edits; (4) evict a transport file, disconnect, lock a file and restart mid-publish; local recordings still work and recovery has no loss or phantom deletion; (5) verify profile matching, explicit opt-in/revoke and source deletion on both with invented voices; (6) later, record on both at once, transfer only finalized bundles, prove read-only remote/edit refusal, audio-only and full deletion propagate, no resurrection after old device returns; (7) disconnect/re-pair and inspect provider copies and local recovery evidence. Keep numeric results and test version; no private content. Exact-head checks, independent review and owner acceptance on both devices. Tests planned over 20 minutes need owner approval.
