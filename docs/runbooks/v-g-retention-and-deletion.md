# V-g — retention and deletion verification

Scope: V1 cell V12 / Must 10. Use invented meetings and a disposable library. Do not use an owner's profile, library, or recordings. This pack checks the source behavior and test harnesses; it does not claim installed-build acceptance.

## Test setup and checks

For automated rows, use `npm ci`, then `npm run check` and `npm run check:register`. The storage and app-core tests need no installed build. The Electron spec is an unpackaged real-backend run in the style of `apps/desktop/e2e`: it sets `SCRB_DEV_AUTO_LOCATION=1`, passes an explicit `--user-data-dir` under the OS temporary directory, and writes `library-location.json` pointing to a separate temporary library. Do not operate the location dialog by hand or through UI automation.

Seed each candidate with a `meeting.json`, `transcript.json`, `summary.json`, an `exports/` file, microphone and meeting audio files, `voices.json`, and one `voice_profile_meetings` contribution. Add a fresh control meeting with the same file set. Set age from `meetings.created_at`/`MeetingRow.createdAt`, which is when the meeting entered this library; do not age from the source recording's date. Check files under `meetings/<folder>/`, `cache/<meetingId>/`, and the SQLite `meetings` and `voice_profile_meetings` tables. Example read-only checks:

```sql
SELECT id, audio_deleted_at FROM meetings WHERE id = ?;
SELECT profile_id, meeting_id, sample_count, model_id
  FROM voice_profile_meetings WHERE meeting_id = ? AND embedding IS NOT NULL;
```

After an audio purge, a plain profile link may remain, but its contribution columns must be `NULL`; after a meeting purge, its link row is gone too.

Each matrix row is a separate setting choice. Mark one status after execution: `Pass` or `Fail`.

## Defects found

- **Audio deletion can report success while retaining voice data.** [`packages/storage/src/library.ts`](../../packages/storage/src/library.ts) in `deleteAudioLocked` catches a failure removing `voices.json`, then continues deleting audio. Its final `remaining` check only covers the audio tree and cache, so the report can be successful while `voices.json` and the associated contribution rows survive. This breaks the approved purge rule in [`docs/plans/voice-profile-growth.md`](../plans/voice-profile-growth.md). Minimal fix: abort/return a failed delete when `voices.json` cannot be removed, and include it in `remaining`; do not drop contribution rows unless the voice file is purged. Not changed here because that is production behavior.
- **The 1-year rule is a fixed 365 days.** [`packages/storage/src/library.ts`](../../packages/storage/src/library.ts) defines `1y` using `365 * DAY_MS`, so a leap-year anniversary is not represented. The requirements say “1 year” without defining calendar versus fixed-duration semantics. Minimal fix after the owner chooses the intended rule: compute the cutoff by calendar anniversary or state and test the 365-day convention. No behavior change made.
