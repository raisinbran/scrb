# V-g — retention and deletion verification

Scope: V1 cell V12 / Must 10. Use invented meetings and a disposable library. Do not use an owner's profile, library, or recordings. This pack checks the source behavior and test harnesses; it does not claim installed-build acceptance.

## Test setup and checks

For automated rows, use `npm ci`, then `npm run check` and `npm run check:register`. The storage and app-core tests need no installed build. The Electron spec is an unpackaged real-backend run in the style of `apps/desktop/e2e`: it sets `SCRB_DEV_AUTO_LOCATION=1`, passes an explicit `--user-data-dir` under the OS temporary directory, writes `library-location.json` pointing to a separate precreated temporary library, and passes `--scrb-isolated-test-profile`. Verify the selected canonical library root and seeded fixture IDs through read-only calls before user-driven changes. Do not operate the location dialog by hand or through UI automation.

Seed each candidate with a `meeting.json`, `transcript.json`, `summary.json`, an `exports/` file, microphone and meeting audio files, `voices.json`, one `cache/<meetingId>/` file, and one `voice_profile_meetings` contribution. Add a fresh control meeting with the same file set. Set age from `meetings.created_at`/`MeetingRow.createdAt`, which is when the meeting entered this library; do not age from the source recording's date. Check files under `meetings/<folder>/`, `cache/<meetingId>/`, and the SQLite `meetings` and `voice_profile_meetings` tables. For audio-only deletion, verify the seeded cache is gone and transcript, summary, and export contents are unchanged; for whole-meeting deletion, verify all seeded files and rows are gone. Example read-only checks:

```sql
SELECT id, audio_deleted_at FROM meetings WHERE id = ?;
SELECT profile_id, meeting_id, sample_count, model_id
  FROM voice_profile_meetings WHERE meeting_id = ? AND embedding IS NOT NULL;
```

After an audio purge, a plain profile link may remain, but its contribution columns must be `NULL`; after a meeting purge, its link row is gone too.

Each matrix row is a separate setting choice. Mark one status after execution: `Pass` or `Fail`.

## Defects found

- **Audio deletion could report success while retaining voice data; fixed in #522.** `deleteAudioLocked` now checks for remaining `voices.json`/suggestion data and refuses to remove audio when that purge or contribution cleanup fails. It reports `ok=false` and leaves the meeting eligible for a later startup or scheduled sweep; see `delete-audio fails and keeps the audio while voices.json cannot be removed` in [`packages/storage/test/voice-contributions.test.ts`](../../packages/storage/test/voice-contributions.test.ts). The verification case remains in this matrix; this is no longer an open defect.
- **Gate 7 E2E profile setup was not fail-closed.** [`apps/desktop/e2e/real-gate7-walkthrough.spec.ts`](../../apps/desktop/e2e/real-gate7-walkthrough.spec.ts) placed the library inside user data and omitted `--scrb-isolated-test-profile`, contrary to the isolated test-profile rule. The minimal fix is separate precreated temporary profile/library directories, the isolation switch on each launch, and read-only checks for the selected root and fixture IDs before UI actions.
- **Retention matrix fixtures did not prove cache removal or text-side preservation.** [`packages/storage/test/retention-verification.test.ts`](../../packages/storage/test/retention-verification.test.ts) had no cache, summary, or export file to check, and its existence helper treated every access error as absence. The minimal fix is seed nonempty invented files, assert their contents/removal explicitly, and rethrow errors other than `ENOENT`.
- **The 1-year rule is a fixed 365 days.** [`packages/storage/src/library.ts`](../../packages/storage/src/library.ts) defines `1y` using `365 * DAY_MS`, so a leap-year anniversary is not represented. The requirements say “1 year” without defining calendar versus fixed-duration semantics. Minimal fix after the owner chooses the intended rule: compute the cutoff by calendar anniversary or state and test the 365-day convention. No behavior change made.

Production starts an auto-delete sweep when the backend opens and schedules another sweep every six hours. A failed audio purge remains eligible, so the next startup or scheduled sweep attempts it again. The explicit second sweep above is a deterministic test step; the product does not promise a user-triggered retry action.
