## Findings, ranked by real risk

### SP-01 — Medium: private library files inherit permissive access

- **Evidence:** `packages/storage/src/library.ts:227-232,319-324` creates directories without a mode; `packages/storage/src/atomic.ts:60` opens private document temporaries with `wx` without a mode; `packages/storage/src/db/database.ts:11-18` configures SQLite durability/erasure but no filesystem access policy. `native/windows-capture/src/ChunkStore.cpp:160` inherits the directory's security descriptor. In contrast, macOS audio chunks explicitly use 0600 (`native/macos-capture/src/Chunks.swift:46`).
- **Risk:** privacy leak to another local account or a shared-folder reader, covering transcripts, corrections, summaries, vocabulary and biometric embeddings. Disk encryption protects a locked disk, not another account's permitted access while mounted.
- **Trigger / likelihood:** the user selects a shared/traversable library, or uses a parent directory with permissive access. Conditional; lower in a private home folder. An invented probe with umask 022 produced directory 0755 and transcript 0644 using the real atomic writer. No real library permissions were inspected; actual Windows ACLs and installed-build behavior remain unverified.
- **Smallest fix:** create private roots/directories as 0700 and sensitive files as 0600 on POSIX; check existing access and inherited Windows ACLs, warning before use of a shared root. Do not silently rewrite user-selected shared-folder ACLs. Verify with another ordinary account on both systems.

### SP-02 — Medium: “whole meeting” deletion retains learned voice data and vocabulary

- **Evidence:** `packages/storage/src/db/meetings-index.ts:108-119` deliberately deletes profile links and vocabulary contexts but keeps profiles and terms; `indexTraces` at `:127-139` checks only links. `packages/storage/src/db/voice-profiles.ts:142-152` folds samples into an aggregate embedding; no per-meeting contribution is retained to subtract later. `packages/storage/src/library.ts:1092-1103` can therefore return no remaining traces while these learned values persist. The existing test explicitly expects the profile to survive with empty meeting IDs (`packages/storage/test/library.test.ts:345-363`). Auto-delete uses the same methods (`library.ts:1197-1201`).
- **Risk:** privacy retention, particularly a named or orphaned biometric profile derived solely from the deleted meeting. Learned names/terms can also remain. This is intentional cross-meeting learning, not proof of a coding accident, but “whole meeting” and “nothing left behind” do not mean erasure of all derived personal data.
- **Trigger / likelihood:** ordinary deletion after profile building or remembered corrections; common when those features are used. Audio-only deletion also intentionally preserves profiles, text and vocabulary.
- **Smallest fix:** explicitly disclose retained learning in delete/retention confirmation and offer a separate derived-data removal choice. Remove orphan profiles when that choice is selected; rebuild multi-meeting aggregates from retained sources rather than claiming subtraction is possible. Keep the separate profile-delete control. Owner decision needed on the lifecycle semantics; do not silently destroy global learned vocabulary/profiles.

### SP-03 — Medium: downloads are verified only after an unbounded body is written

- **Evidence:** `apps/desktop/src/main/model-download.ts:200-207` checks free space once; `:261-263` gives the archive no expected byte count; `:294-308` streams without a byte ceiling; size rejection/hash verification happens at `:315-327`. Model installation does correctly require the pinned digest.
- **Risk:** local availability / potential recording data loss if the volume fills. Hash checking prevents installation of a malicious model but cannot undo disk exhaustion during its download.
- **Trigger / likelihood:** an oversized or never-ending response from an allowed HTTPS host/CDN, or free space consumed concurrently. Uncommon; this is not an arbitrary Internet caller's direct attack, and no actual lost recording was reproduced.
- **Smallest fix:** abort streaming as soon as the pinned size is exceeded, pin an archive size or conservative cap too, and check available space periodically. Refuse/pause downloads during capture if they share a constrained volume. Keep checksum verification before rename.

### SP-04 — Low: vocabulary hints and meeting paths are visible in child-process arguments

- **Evidence:** `packages/transcription/src/whisper.ts:42-67` passes a vocabulary hint in `--prompt` and WAV/output paths as arguments. `packages/app-core/src/final-pass.ts:97-104` supplies that hint. Capture uses a pipe for commands (`packages/capture/src/process-adapter.ts:23-25`); transcription uses `shell: false` (`packages/transcription/src/worker.ts:49-58`).
- **Risk:** local privacy leak of learned names/terms, and title-bearing paths, through process inspection or diagnostics collected by the OS/support software; no shell execution from those strings.
- **Trigger / likelihood:** another account/process with permission to inspect arguments while inference runs, or an OS crash/support report. Conditional and transient. Actual cross-account process visibility and crash capture were not tested.
- **Smallest fix:** send prompt material over an owned pipe/stdin or use a 0600 temporary input supported by the helper; use opaque scratch paths. Document what OS diagnostics may contain and avoid collecting command lines in support bundles.

### SP-05 — Low: final-pass manifests lack the secure playback path's validation

- **Evidence:** `packages/app-core/src/final-pass.ts:97-111` joins `chunk.file` from local `chunks.json` without a basename allowlist, realpath containment or symlink checks. Playback instead validates names and membership and checks realpaths (`apps/desktop/src/main/playback-media-source.ts:43-51,171-198`).
- **Risk:** local file read outside the intended meeting, potentially transcribing another decodable audio file into the meeting. This does not establish arbitrary code execution or an off-device leak.
- **Trigger / likelihood:** a locally modified/copied library manifest containing `../` components, or a symlink substitution, followed by final processing. Low: native writers and the normal import flow generate their own chunk names, and an attacker already needs library write access. Source-confirmed path construction; no external file was read.
- **Smallest fix:** reuse the strict sealed-chunk resolver for final-pass inputs; validate schema, numeric bounds, filenames, containment and symlinks before handing paths to helpers. Close parent-directory races where practical. Do not classify this as a remote exploit from an ordinary audio import.

### SP-06 — Low: main event dispatch has no runtime name allowlist

- **Evidence:** `apps/desktop/src/preload/preload.ts:13-35` allowlists calls and events. `apps/desktop/src/main/dispatch.ts:14,25-30` allowlists call names and validates requests. Main's event publisher sends its supplied name directly (`apps/desktop/src/main/main.ts:334-338`); `:215` has another literal-name send. Types constrain ordinary callers, but `EVENT_NAMES` is not checked at runtime in main.
- **Risk:** hardening only / a repository security-rule gap. No renderer-controlled unknown-event route was identified; this alone grants no new privilege.
- **Trigger / likelihood:** a future untyped producer or erroneous cast; low in current code.
- **Smallest fix:** centralize all event sends behind a runtime `EVENT_NAMES` set check (and, preferably, payload validation), retaining the one event channel. Do not add another IPC channel.

### SP-07 — Low: dependency advisories and two non-exact external declarations

- **Evidence:** `packages/summary/package.json:15-16` uses `^22.0.0` and `^5.9.0`; other external direct declarations inspected are exact. Internal `@scrb/*: "*"` entries are workspace links, not floating registry downloads. The committed lockfile fixes resolved versions. Audit details follow below.
- **Risk:** development/build availability via vulnerable glob/XML parsing; reproducibility drift if the lockfile is regenerated. No production meeting-data leak was demonstrated.
- **Trigger / likelihood:** pathological source/glob/XML input reaches the affected build or test utilities; low for the installed app. All 15 flagged entries are marked `dev: true` in the root lockfile. Native runtimes and Electron's bundled Chromium are outside npm audit's coverage.
- **Smallest fix:** separately review advisory-specific updates, pin the two declarations exactly, regenerate and verify the lockfile in a dedicated change. Do not apply the audit's proposed bulk downgrades blindly. No dependency changed here.

### SP-08 — Medium, conditional: opaque URL origins collide in packaged navigation and IPC checks

- **Evidence:** `apps/desktop/src/main/main.ts:50-56` calculates the packaged app origin with Node `new URL(appUrl).origin` and compares the sender frame using the same property. `security.ts:46-49` uses that comparison to allow navigation. An invented Node probe returns the same literal `null` string for `scribe://app/index.html`, `scribe://evil/index.html`, `file:///tmp/invented.html` and `data:text/html,invented`. Registering a Chromium scheme does not itself make Node's URL parser identify a trustworthy host.
- **Risk:** conditional local exploit / privacy leak or data loss: if hostile local HTML executes in the existing main window, its preload bridge can reach allowlisted backend operations and its frame passes this main-side URL test. There is no default-session request firewall comparable to the print session; such a page would not inherit the original built page's meta CSP. No arbitrary Node privilege or remote exploit is claimed.
- **Trigger / likelihood:** requires a way to navigate an owned window to attacker-controlled content. **No current ordinary UI entry route or end-to-end exploit was demonstrated.** In particular, the pinned [Electron 45.2.1 preferences documentation](https://github.com/electron/electron/blob/v45.2.1/docs/api/structures/web-preferences.md) says drag/drop navigation defaults to false, so this review does not assert that dropping a file works. A future navigation/link path or a changed runtime default could expose the failed boundary. Low demonstrated likelihood, substantial conditional impact; actual registered-scheme sender behavior and installed navigation remain unverified.
- **Smallest fix:** compare explicit protocol/hostname/port against the exact `scribe://app` tuple, reject opaque/file/data/about URLs, catch URL parse errors, and bind IPC to the app-owned main frame/window. Apply the same predicate to navigation/redirects; explicitly disable drag/drop navigation. Add pure URL rejection tests plus invented-content installed Electron checks. Never equate two serialized `null` origins with trust.

## Deletion and path/process review

Whole-meeting deletion renames to `.deleting-ID`, removes that folder plus cache/ID, deletes index/context links, checks remaining paths and recovery copies, and reports failures (`library.ts:1026-1131`). Audio-only removes audio and cache, then records audioDeletedAt only on success (`:1135-1156`). Auto-delete defaults to Never, selects by library creation time, defers for recording and rechecks active writers (`:1047-1058,1161-1207`); scheduled at startup and six-hour intervals (`:1214-1233`). Playback is revoked and summaries stopped before retention/manual delete (`backend.ts:250-253,369-381`). SP-02 describes derived learning that survives.

Profile deletion unlinks saved transcript speaker layers/history before deleting the profile (`library.ts:496-557`); profile-store delete clears its undo/redo (`db/voice-profiles.ts:275-279`). SQLite uses secure_delete ON and DELETE journal, not WAL (`database.ts:11-18`). Upgrade snapshots can retain older data; deletion reports those rather than claiming clean success (`library.ts:1100-1117`). Filesystem unlink is not secure erasure of SSD blocks, backups or user copies; that is consistent with reliance on OS encryption. Original imported audio stays outside the library by design and is never deleted.

Final-pass scratch is under cache/meeting-ID/final-pass and removed in finally; interrupted passes resume or remove it (`app-core/src/final-pass.ts:236-237,356,381-392`, `transcription/src/finalPass.ts:140-141`). Import staging cache/imports is cleaned on failure and scanned on startup (`imports.ts:75-88,168,313-318`). Cleanup failure is reported, not erased from evidence. Completed exports under a meeting disappear with its folder; external copies, OS recent-file metadata/crash dumps and global live-trace metadata are outside that deletion. No app-run or crash/power-loss erasure verification occurred.

Titles are sanitized into a bounded folder component (`layout.ts:63-87`); meeting IDs/index folder components reject slash, backslash, NUL and dot/dotdot. Import uses an OS-picked file token with a ten-minute lifetime, not an arbitrary renderer path (`imports.ts:93-142`), and creates its own staging path/UUID. ffmpeg/ffprobe receive argument arrays (`importFile.ts:91-144`, `audio.ts:103-113`); no shell interpolation from title/speaker/import fields was found. Speaker names remain data in JSON/parameterized SQL and escaped documents. Export uses a sanitized stem, exclusive file claims and realpath containment within the library (`export.ts:63-92,139-142`). It only checks containment in the library, not the selected meeting; a locally replaced exports symlink inside another meeting could misdirect an export. Treat shared-directory/symlink attackers as low-priority local hardening (SP-01/SP-05), not an ordinary title injection.
