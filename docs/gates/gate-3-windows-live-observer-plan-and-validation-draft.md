## 1. What was built (offline, unrun)

| File | Role |
| --- | --- |

**Rules implemented**

- **Visible:** a word counts only if its bounds lie fully inside the viewport rectangle read in the same sample and its element is not reported off screen. If only paragraph bounds exist, the paragraph must be fully inside, and those words are marked `bounds_source: element`.
- **Stable word id:** `track|row time text|word index`, for example `microphone|0:05|3`. Track comes from the row's speaker label (`You` is microphone; `Meeting`, `Speaker ?` and `Speaker N` are meeting, in `track_for_label`; any other label with words makes the run INCONCLUSIVE; `--label` adds explicit mappings). The id does not depend on screen position or scrolling. Two rows with the same track and time text in one sample are excluded and reported.
- **First visible only:** later polls of the same id are dropped. A later change of a position's text is listed under `text_revisions` and not published; the matcher cannot ingest revisions.
- **Time:** `observed` = sample end, in seconds on the harness QPC clock = (QPC ticks − harness origin ticks) / frequency. The harness log (`play-sources.ps1`) already records `qpc_ticks` and `stopwatch_frequency` from the same `Stopwatch`. A frequency mismatch is refused.
- **Uncertainty:** `u` = this sample's end − the previous successful sample's begin, which is the gap plus both read times. A failed sample is skipped, so it widens `u`. This is wider than the old reach probe, which used end minus the previous end. Largest `u` over 250 ms is listed. Words already on screen at the first sample are flagged `present_at_start`; their `u` runs from the observer origin and they are not counted as over the limit.
- **Quarantine (cross-sample collisions):** a row key (track plus displayed time) is quarantined for the whole run, and any earlier records for it are removed, when it cannot be the same row everywhere it was seen: two rows with that key in one sample, or a return after absence or a read-error gap with different or shorter text. A quarantined or excluded row gets no publication, so its reference utterances are uncredited in both the conservative and the best-case bound and stay in the denominator. They are reported under `quarantined_rows`. A contiguous change with no absence is a revision, reported, not a collision. A row replaced by another row with identical or prefix-extending text and the same displayed timestamp, while it stayed on screen, cannot be detected by the observer (there is no absence, shorter text or second row to trip the quarantine rules). This is a known residual, documented and not fixed.
- **Largest `u` over all intervals:** the report's `u_all_intervals_max_s` covers every polling interval (origin to first sample, each sample to the next, and a trailing read-error stretch), with read errors widening the interval they sit in. `u_pass` is true only if that maximum is 250 ms or less. The per-publication `u_max_s` is kept but is not the acceptance figure.
- **PROPOSED rule change (owner approval pending; independent review pending; not frozen):** the `Live transcript` element exists only while recording, so an observer started before **Record** (checklist order) always has one long interval from its start to the first sample that found the viewport. Under the proposal the 250 ms limit applies to every interval from the first sample that found the viewport onward (including read-error stretches after it), and the single earlier interval is reported as `pre_viewport_interval_s` and not counted toward `u_pass`. If the first found sample already holds visible words, the report says `result_status: INCONCLUSIVE` (the observer started too late for that run). Tests: `PreViewportInterval` in `test_observer_publications.py`.
- **PROPOSED visibility rule (owner approval pending; independent review pending; not frozen):** keep the original protocol rule: a word counts as visible only when **its own bounds** lie inside the viewport rectangle read in the same sample and its element is not reported off screen, checked on at least 10 frames/samples that include scrolling and virtualization. Finding from observer-validation-3: the app exposes **each word as its own UIA Text element with its own bounds** (all 1186 publications are single words; `bounds_source: element` means that word element). The earlier paragraph-level proposal (whole paragraph must be inside) is therefore withdrawn as unnecessary; the paragraph fallback in the first bullet stays only for a build that merges words into one element. The earlier report that called these bounds paragraph-level was wrong (register A-052).
- **Virtualization evidence from the data:** `virtualization_evidence` finds rows that left the accessibility tree (not merely the viewport) and returned later with the same text, and rows that moved on screen between samples. A row outside the viewport but still in the tree does not count. A typed "scrolled" or "virtualized" flag in a review item is ignored. **Measured on observer-validation-3 (correction of an earlier wrong statement, A-052):** the app keeps a rolling window of about 18 rows in the tree and drops the oldest as new rows arrive (from 54 s, before any scrolling); scrolling up brought 165 rows back, 164 with unchanged text and 1 re-segmented under the same speaker and displayed second. The 165 rows that were absent at the end had aged out of that window; they are not a failure. PROPOSED check: pass needs at least one removal followed by a return, identity preserved for every non-quarantined return, and pane motion; rows aging out must not count against it.
- **Not done by the observer:** the 100 ms marker fit and the harness-to-recording mapping stay in `marker_clock.py` and the matcher.

The scripts parse with the PowerShell parser; they were never run.

**Integration additions (this branch).** `observer_session_map.py` converts observer publication times (harness Stopwatch ticks) to the session's timestamped-capture seconds with one subtraction, `seconds = ticks/frequency - session_origin`, and applies a conversion error e as `observed = nominal + e`, `u = polling_u + 2e` (the scorer reads a publication as lying in [observed - u, observed]). The origin is the **reconstructed effective origin** (device stamp minus embedded start, recomputed from the chunk rows and required constant across the track; 553dd90's app logs no `clockOriginNs`; a logged value, if ever supplied, must equal it). Nothing is passed as a bare argument: the observer raw header, the harness log (frequency and tick order), the publication file (origin ticks, frequency), the track and session identity, the ordered source chunk hashes, the metadata hash and the conversion uncertainty (at least one counter tick, with its stated basis) must all agree, are recorded in the output's `conversion` block for the freeze record, and any mismatch or absence raises before matching. No marker fit is used. `test_lead_and_session_map.py` (15 tests) covers it, the conversion-error rule, the evidence checks, overlap placement and the lead-marker anchor. `test_integration_e2e.py` (18 tests, no skip paths) runs invented observer records through publications, the session mapping, the occurrence matcher, v3a timing and analyze-bounds: 15 repetitions of one sentence, a quarantined row that stays in the denominator, a unit crossing a gap, steps of both signs, publications near 6 s, the lead-marker anchor, and missing or invalid clock evidence never passing.

**Conversion allowance and scorer binding (proposal, owner approval pending).** The 2 ms conversion allowance is a conservative numerical allowance for converting between two QPC-based clocks (Stopwatch ticks and capture timestamps); it is not measured device timestamp accuracy and not a bound on playback or capture delay. If the same-counter assumption or the origin reconstruction fails, the affected timing is INCONCLUSIVE. `analyze-bounds.py --mode v3a` now takes the converted file, the raw observer file and the harness log by path, binds every credited endpoint to the converted file by id, observed time and u, and records the SHA-256 of all three files; the freeze record lists the pinned native candidate, QPC frequency, conversion method, reconstructed effective origin, the 2 ms allowance with this basis, and those hashes.

**Word-level vs paragraph-level handling (code reading, unverified on the real screen).**

- `observe-live-v2.ps1` asks TextPattern for each word's rectangles. `GetBoundingRectangles()` returns an array of rectangles, one per line the word covers. One rectangle is a normal word (the earlier code wrongly required four or more and dropped such words; fixed). Several rectangles are united. Empty rectangles are dropped; a word left with none is written with `bounds: null` and the adapter treats it as not visible.
- If the element has no TextPattern or the call yields no words, the `words` list is empty and the adapter falls back to the paragraph's bounds: all its words count as visible only if the whole paragraph is inside the viewport, and each such record carries `bounds_source: element` (the report counts them). A paragraph clipped at a viewport edge then shows no visible words, which can delay a first-visible time.
- Single-word elements skip the TextPattern call; the element is the word.

**To check on the real Live screen:** (a) which of the two paths the pane yields; (b) that the word units match the sentence words (UIA word splitting of apostrophes, hyphens and trailing punctuation) and the matcher's normalized tokens; (c) that word rectangles are in the same screen coordinates as the viewport rectangle (including display scaling and a window that is not at 100%); (d) rectangles for words outside the viewport: empty, or present but outside; (e) wrapped words; (f) the extra read time of `-WordBounds` per sample.
