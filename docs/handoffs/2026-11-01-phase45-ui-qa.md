# Early Phase 4/5 UI verification on the mock backend

**Base:** main `9018e42`. Preliminary; not gate evidence. Checked in the mock UI at localhost:5183 and by tests. Real diarization, vocabulary tuning and the native app were not exercised.

## Fixed in this branch

- Transcript rows had plain speaker names, so Reassign and Split selection could not be reached, although Speakers told users to select words in the transcript. Rows now use the speaker menu. Only the line with the cursor or selection is a Tab stop.
- Losing a selection under an open editor left it marked as editing: focus fell to the page and the editor reopened on the next selection.
- Undo state was not read from `getUndoState`, so it was blank after a reload or a change made elsewhere.
- Pending suggestions were not loaded with `listSpeakerSuggestions`, so any raised before the app opened never appeared.
- Vocabulary had no Undo or Redo, which the Requirements section on corrections and vocabulary needs ("Undo and redo work on all edits"). Voice profiles had none for rename and merge.

## Open, not changed here

1. `importAudio` returns `privacyBannerRequired`, but nothing in the UI uses it, so an opted-in import in a listed location shows no banner. Requirements call for one. Left for the Task 18 import branch to avoid overlap.
2. Meeting-level speaker rename and merge return nothing and add no undo entry on the mock, so they have no Undo. Whether the requirement covers them is an owner or backend decision.
3. Vocabulary has no manual add. The contract has no add call, so Remember correction is the only way in. Add one only if the owner wants it.
4. The finished-meeting Transcript tab is read-only: no correction or speaker menu. Requirements say speakers can be fixed "at any time"; today that goes through the Speakers screen.
5. `hybrid-backend.ts` sends corrections, undo and speaker calls to the mock, so none of this reaches real meetings yet. PR 27 touches that file.
