# Recordings UI: what the contract lacks

- [x] From: Recordings UI session. To: the owner, for contract approval, and the backend sessions.
- [x] Needed: the gaps below. None was worked around outside `Backend`. Each says what the UI does today.
- [ ] Contract items affected: listed per gap.
- [ ] Screens affected: Recordings, meeting detail, Summary tab.
- [ ] How to test: run `npm run dev`, open the developer menu with Ctrl+Shift+Alt+D, and use the Recordings and Summary groups.

| #   | Gap                                                                                                                                  | Needed                                                                                         | UI today                                                                                                                         |
| --- | ------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 1   | No event says a meeting changed, so nothing announces the end of a final pass                                                        | A `meetingChanged` event carrying `MeetingListItem`                                            | Polls `listMeetings` and `getMeeting` every 3 s while a meeting is in a passing state                                            |
| 2   | Imports: the privacy banner must show when profile building is on and the location rule applies, and only the backend knows the rule | `privacyBannerRequired` on the `importAudioFile` response, or a call that asks before starting | No banner is shown for imports. This is a requirement not met yet                                                                |
| 3   | No call lists running imports                                                                                                        | `listImports`, or an `importing` meeting that carries its `importId`                           | A tracker outside the screen survives navigation. After a window reload, a running import reappears on its next `importProgress` |
| 4   | `MeetingDetail` does not say whether audio still exists, and auto-delete can remove audio only                                       | `hasAudio: boolean`                                                                            | Player and Audio tab always show. A failed seek shows its error                                                                  |
| 5   | `SummaryItemUpdate` can change an item but not add or remove one                                                                     | `add` and `remove` kinds                                                                       | Items can only be edited                                                                                                         |
| 6   | Whether a `fileToken` can be reused is not stated                                                                                    | State it on `PickedAudioFile`                                                                  | "Try again" reuses the token after a recoverable failure                                                                         |
| 7   | `searchMeetings` takes no filter                                                                                                     | An optional `MeetingFilter`                                                                    | Filters apply to the results in the UI                                                                                           |
| 8   | `cancelImport` says only `importCancelled` means no meeting exists, but V1 Requirements say a failed import also leaves none         | Reword the comment, or confirm which is meant                                                  | The UI tells the user that no meeting was created                                                                                |

`MeetingFilter` date bounds are ambiguous too: the UI sends local calendar days, while `startedAt` is UTC. A meeting near midnight can land in the neighbouring day. The contract should say which day applies.
