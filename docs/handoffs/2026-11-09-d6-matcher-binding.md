# D6 scope: what binds the scored outcomes to the occurrence matcher (2026-11-09 PT)

Finding (review of a35c4bd): the unit list the scorer reads (`data['units']`) is a hand-passed JSON. `analyze_v3a_track` bound each credited **endpoint value** to a word of the converted publication file (`bind_endpoints`) but never checked that `outcome`, `identity_confirmed` or the endpoint-to-utterance assignment came from `occurrence_matcher`. An edited outcome (for example UNIDENTIFIED to MATCHED) or two units' endpoints swapped would have been accepted whenever the values existed in the converted file. The scorer does not regenerate the rows from the matcher.

Fix made (smallest): `evidence['matcher_output']` is now required. `bind_matcher_output` loads that file (the matcher's own `OFFLINE_ALIGNMENT_ONLY` output), requires the same track, clock basis and recording SHA-256 as the converted publication file, and requires every credited unit (eligible and MATCHED, MATCHED-SUBSTITUTED or BOUNDED) to equal the matcher row on outcome, `identity_confirmed` and the ordered endpoint publication ids; any mismatch makes the track INCONCLUSIVE. The file's SHA-256 is reported as `evidence_hashes.matcher_output_sha256`. Regression: `test_hand_edited_unit_assignments_that_differ_from_the_matcher_output_are_rejected` (swapped endpoints, upgraded outcome, forged identity; the genuine case still passes).

Still open: the matcher output file itself is only hashed, not regenerated, so someone who edits both the unit list and that file consistently is not detected. Proposal (not built; it needs the frozen annotation to be the exact matcher input): have `analyze_v3a_track` call `occurrence_matcher.align_occurrences(frozen annotation, converted words, track, clock_basis='recording')` itself and compare, as `regenerate_converted` already does for the conversion. The owner decides whether that redesign is wanted before a scored run.
