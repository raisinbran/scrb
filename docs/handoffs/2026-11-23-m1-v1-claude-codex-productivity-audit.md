**Bottom line — accepted delivery first:** **Neither November 8–15 (Claude available) nor November 16–22 (Claude unavailable) produced a newly approved full-project gate, a completed installed M1, or an accepted V1.** Formal installed evidence remains M1 **0/15** and V1 **0/28** verified, not measured failure. ## 1. Evidence and limits of attribution

The owner identified two **Claude-access** windows (availability of Claude Code and/or Claude chat; the task records cannot reliably distinguish the two modes), **October 27–November 3** and **November 8–15**, and two **ChatGPT/Codex-only** windows, **November 4–7** and **November 16–22**. The labels below are **calendar availability regimes**, not assertions that Claude personally authored every changed line or operated every machine on those days. The GitHub author is typically the owner's account; its commit metadata cannot identify the AI/model that performed the work. For example, the [Mac Gate 3 record](../gates/gate-3-macos.md) explicitly credits the physical runs to Codex and a later evidence review to Claude. Do not attribute that gate solely to either tool.

Daily grouping uses **commit committer date, not author date**, PR merged_at, and Actions created_at, converted to America/Los_Angeles including the Nov 1 DST transition. The pinned SHA b75bd7f42ec3540751baa31ae59bf0c9485bb059 returned **1,112 unique commits** (11 full pages + 12, then empty). The original Nov 23 PT audit fetched **433 PRs** before PR #456 was created; later totals grew without affecting the historical cutoff. CI includes only completed success/failure runs for .github/workflows/ci.yml, deduplicated by workflow-run ID; each contributes **one latest observed conclusion at the Nov 23 PT audit**, including any prior job retry. It does not measure first-attempt or per-task success. Daily aggregates and exact UTC boundaries are in §7.

**Critical caveats:** Commit timestamps are not the date a branch entered main; stacked/non-squash history inflates early totals; merges can admit earlier-dated commits; PR size, merge style, task complexity and project phase vary substantially. Source integration versus installed-package hardening is a central confounder. PR titles are only an approximate code-versus-documentation classifier. No reliable, comparable task-hours, task-attempt denominator, QA-defect severity denominator, or Claude-vs-Codex device execution log is available; **an actual task success percentage or causal per-model productivity claim would be fabricated**. CI run success and merge throughput are measurable proxies, not substitutes for user delivery.

## 4. Why the Nov 16–22 delivery rate stalled

**Observed operational failures, separate from app quality:**

1. **Codex execution capability mismatches and repeated host-context failures.** BCHEN-W10 Git CLI configuration permission denied; sandboxed Git metadata writes denied despite ordinary file reads/writes; constrained CUA GUI control stalled; some cloud GitHub sessions can inspect or rerun Actions but **cannot create a new workflow dispatch**. The proper outcome should have been a single bounded capability assessment and handoff, not repeated loops. See [Nov 18 blocker handoff](2026-11-18-codex-blockers-m1-v1-installed-delivery-handoff.md), [M1 Mac crash issue #357](https://github.com/raisinbran/scrb/issues/357), [installer issue #419](https://github.com/raisinbran/scrb/issues/419).
2. **Mac Electron startup abort before any Scribe code.** The current isolated package built from **b75bd7f42** passed static checks; one bounded direct launch exited **134/SIGABRT** during HIServices/AppKit application registration, before UI/backend/library creation. Existing [Electron issue #52815](https://github.com/electron/electron/issues/52815) and [Codex issue #30043](https://github.com/openai/codex/issues/30043) describe a **possible** sandbox/Mach-service failure mode, **not confirmed on M5**. No repeated launch is warranted without comparison to existing crash and unified logs. Preserve production app and rollback; do not infer recording failure from this startup crash. [Read-only task #340](https://github.com/raisinbran/scrb/issues/340#issuecomment-7088387144).
3. **Windows installer workflow was authorized but skipped before runner allocation.** [Run #45086217075](https://github.com/raisinbran/scrb/actions/runs/45086217075) has correct actor, source and first-attempt metadata; the specific false job-level conjunct is not shown. Do **not** assert an unchecked opt-in as a proven cause. [Diagnostic PR #454](https://github.com/raisinbran/scrb/pull/454) adds nonsecret run-name inputs without relaxing ten authorization checks. It then suffered **basic avoidable ESLint and CRLF-sensitive test assertion failures** before reaching a corrected head, **3d7686cafb2eb945aae56dad1eeec5e571818b67**. Latest checked [application CI #45126047442](https://github.com/raisinbran/scrb/actions/runs/45126047442) and [source checks #45126047444](https://github.com/raisinbran/scrb/actions/runs/45126047444) both **PASS**. **No formal review or merge as of this audit**. Run #45086217075 consumed its distinct one-dispatch authorization; another genuine 130-minute attempt needs a new exact-SHA owner decision after guard diagnosis. Do not use Re-run.
4. **Recurrent unrelated flaky or misleading CI faults.** [Issue #380](https://github.com/raisinbran/scrb/issues/380) tracks intermittent Windows summary retention deletion result in an unchanged test; a successful targeted retry for [safe-quit PR #444](https://github.com/raisinbran/scrb/pull/444) cleared exact-head CI, **not** the root cause. Separate [PR #452](https://github.com/raisinbran/scrb/pull/452) introduces deterministic barriers and sanitized phase/residue diagnostics. Keep it separately reviewed; do not misattribute the old failed assertion to #444.
5. **Cross-session continuity and administration overhead.** Historic instructions became stale, agents repeated preflights or rediscovered blocked operations, and incident-number collisions/usage accounting spawned multiple docs PRs. The requirement to preserve accounting is valid, but its execution must be batched and kept off M1's runtime critical path. [Three-machine Nov 15 recovery audit](three-machine-recovery-audit-20261115.md) found **163 Mac worktrees (21 dirty)** and **13 BCHEN-W10 worktrees (two dirty)**—strong indicators of environment/worktree coordination cost, not direct app defects. [Nov 18 handoff](2026-11-18-codex-blockers-m1-v1-installed-delivery-handoff.md) explicitly reported the same delivery gap.

**Attribution judgment:** The measured decrease is real at the workflow level. The recurring CI syntax/CRLF mistakes were avoidable agent errors; unimplemented connector capabilities and restricted host permissions are genuine environment limitations; the Mac LaunchServices hypothesis and intermittent retention root cause are **not yet proven**. Neither blaming the Scribe product nor declaring every fault a Codex defect is supported. **Management assessment:** repeated failures without a one-hypothesis stopping rule plausibly impeded installed M1 delivery; their causal time cost cannot be quantified from available records.
